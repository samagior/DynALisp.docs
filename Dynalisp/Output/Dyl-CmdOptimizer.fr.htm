Optimiseur de commandes (Command Optimizer)

Syntaxe Dyl-CmdOptimizer, SAVE, QSAVE, SAVEAS, +SAVEAS, PLOT, PUBLISH, PREVIEW, EXPORTPDF, EXPORTDWF, EXPORTDWFX, REGEN
Fichier source Modules\Dynalisp\Apps\Output\Dyl-CmdOptimizer.lsp
Requis AutoCAD pour Windows (ActiveX / Visual LISP), la préparation de sortie de Resources\dynalisp.mnl
Licence Licence publique générale GNU v3

Description

Redéfinit les commandes de sortie d'AutoCAD pour que le dessin soit préparé avant qu'elles s'exécutent : calques activés et libérés, objets masqués affichés, xréfs rechargées, liaisons de données et tableaux mis à jour, régénération. Les étapes exécutées par chaque commande se cochent dans la fenêtre de préparation de sortie (Dyl-PrepSuite, ou le bouton ouvrir à côté de Commands dans Dyl-Settings), puis la commande native s'exécute comme d'habitude (Ctrl+S lance QSAVE). REGEN est redéfinie avec elles : par défaut, elle applique d'abord le préréglage d'ordre de tracé au dessin (voir Draw Order).

Fonctionnement

  1. Dyl-CmdOptimizer indique si les commandes sont redéfinies et demande Command optimizer, for every drawing [On/Off] <Off>: (Entrée l'inverse). C'est la case Commands de la boîte Overrides de Dyl-Settings : le paramètre utilisateur DynalispPrepRedefine, appliqué tout de suite à ce dessin et aux autres dessins ouverts lorsqu'ils deviennent courants.
  2. Au démarrage, quand la préparation de sortie est activée dans Dyl-Settings, la commande native de chaque commande activée dans Dyl-Suite est retirée avec UNDEFINE : la taper (ou son raccourci) lance la commande Lisp. Le journal de démarrage liste les commandes redéfinies.
  3. Une commande désactivée dans Dyl-Suite garde sa définition native (REDEFINE) : elle n'est jamais laissée indéfinie sans sa commande Lisp. Activer ou désactiver les commandes s'applique tout de suite avec les changements de la Suite (ou Dyl-Reload).
  4. Le désactiver (Dyl-CmdOptimizer ou Dyl-Settings) rétablit les commandes natives dans chaque dessin ouvert; Dyl-RestoreCommands le fait pour la session seulement.
  5. REGEN exécute ses étapes comme les autres commandes : par défaut, seulement Apply the draw order preset (une colonne de la fenêtre de préparation de sortie (Dyl-PrepSuite, ou le bouton ouvrir à côté de Commands dans Dyl-Settings)). L'ordre de tracé réempile l'espace objet, chaque présentation et chaque définition de bloc selon le préréglage actif (comme DO-APPLY), en une seule étape d'annulation, et il est sauté tant que l'ordre de tracé automatique est désactivé (DO-AUTO ou Dyl-Settings). Les autres commandes peuvent l'exécuter aussi : cochez-le dans leur colonne.
  6. Les commandes d'enregistrement (SAVE, QSAVE, SAVEAS, +SAVEAS) exécutent toujours les mêmes étapes : elles partagent la colonne All saves de la grille. Les commandes d'impression (PLOT, PUBLISH, EXPORTPDF, EXPORTDWF, EXPORTDWFX) partagent la colonne All prints; PREVIEW et REGEN ont la leur. +SAVEAS exécute la commande native et vous laisse ses invites, ou à la macro de menu qui l'a appelée.
  7. Dyl-PrepSuite ouvre la fenêtre de préparation de sortie : une grille des étapes (rangées) et des groupes de commandes (colonnes : All saves, All prints, PREVIEW, REGEN), avec All On / All Off. OK l'enregistre tout de suite (Modules\Dynalisp\Res\PrepSuite.csv, votre copie sous User). Le bouton ouvrir à côté de la case Commands de Dyl-Settings ouvre la même fenêtre, enregistrée avec les autres paramètres.
  8. Les commandes appellent la commande native avec le préfixe _. (_.QSAVE...), qui lance toujours la commande d'AutoCAD, indéfinie ou non.

Limites connues

  • UNDEFINE vaut pour toute la session d'AutoCAD, mais les commandes Lisp sont définies dans chaque dessin. Un dessin dont le démarrage de DynALisp s'est arrêté avant le chargement des modules n'a pas de commande Lisp alors qu'un autre dessin a retiré la commande native : tapez-y _.QSAVE (ou REDEFINE), et cherchez l'erreur dans son journal de démarrage.
  • -PLOT et -PUBLISH ne sont pas redéfinies : les scripts et les programmes Lisp les appellent par leur nom ((command "-PLOT" ...)), ce qui échoue tant qu'une commande est indéfinie.
  • PUBLISH est chargée sur demande par AutoCAD (AcPublish.crx); elle est chargée au démarrage pour pouvoir être redéfinie.

Noms des commandes et alias

Chaque programme a une commande principale qui commence par Dyl-. Les noms courts sont ses alias : ils lancent la même commande, et s'ajoutent, se renomment ou se retirent dans Dyl-Suite (enregistrés dans Resources\Aliases.csv). Les rangées marquées ↳ sont les commandes AutoCAD que Dyl-CmdOptimizer redéfinit (voir plus haut).
