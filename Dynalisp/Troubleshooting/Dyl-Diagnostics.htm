Diagnostics

Function Syntax DYL-DIAGNOSTICS
Requires AutoCAD for Windows (PowerShell to zip the report, a GitHub account to send it)
Licence GNU General Public License v3

Program Description

Find out why DynALisp, or AutoCAD with it, does not work as it should. Diagnostics checks how DynALisp is installed and started, the AutoCAD running and what else it loads, the settings and files of DynALisp, its reactors and the current drawing, and writes what it finds in a text report. The problems are marked [!] and listed again at the top.

How To Use

  1. Type DIAG (or click Diagnostics in the Troubleshooting panel of the ribbon). The report opens in your text editor.
  2. Read the problems at the top: each one says what is wrong and, most of the time, what to do.
  3. To get help, answer Open issue: your browser opens a new issue for the developer of DynALisp, its summary filled in, and the folder of the zip of your report. Describe what happened, drag the zip into the issue, then submit it (see Sending A Report).
  4. To check one part quickly, run its command alone (DIAG-DWG for the drawing...): the commands below.

Sending A Report

  • DIAG puts the report, your DynALisp settings and your copies of the data files in a DynALisp Report <date> folder of your temporary folder, and zips it.
  • Open issue opens the new issue in your browser and the folder of the zip; Close keeps the report where it is.
  • A GitHub issue is public: read the report before you send it. The report never holds your profile folder, your user name or your computer name: they are replaced by %USERPROFILE%, %USERNAME% and %COMPUTERNAME%. Your copies of the data files (presets, aliases, layer keys...) are sent as they are. The drawing itself is never sent.
  • Sending it needs a GitHub account; without one, send the zip by email.

Finding What Slows AutoCAD

Pst-DiagnosticsReactorEvents (DIAG-EVENTS) counts the events the drawing sends to the reactors: run it, work the slow way for about 20 seconds (zoom, pan, draw), then run it again. The report lists each event (an object added or changed, a command started, a system variable changed) and its count. The DynALisp reactors run only on these events: when none is counted during a slow zoom or pan, the reactors are not what slows it. It needs the DynALisp reactors on (Dyl-Settings).

The Drawing part times a regeneration of the drawing: run DIAG-DWG, change one thing (the draw order table deleted with DO-RESET, the reactors turned off and the drawing opened again...), run it again and compare.

Known Limitations

  • The compiled programs of other applications (.fas, .vlx, .dll) cannot be read: only their name is listed, not the commands they define.
  • The startup part is the one of the drawing the report is made in; Dyl-Reload records it again.
  • The kinds of objects are counted up to 100 000 objects; above, only their total is given.
