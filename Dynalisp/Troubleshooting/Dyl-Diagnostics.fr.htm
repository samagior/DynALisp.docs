Diagnostics

Syntaxe DYL-DIAGNOSTICS
Requis AutoCAD pour Windows (PowerShell pour compresser le rapport, un compte GitHub pour l'envoyer)
Licence Licence publique générale GNU v3

Description

Trouvez pourquoi DynALisp, ou AutoCAD avec lui, ne fonctionne pas comme il le devrait. Diagnostics vérifie comment DynALisp est installé et démarré, l'AutoCAD en cours et ce qu'il charge d'autre, les paramètres et fichiers de DynALisp, ses réacteurs et le dessin courant, et écrit ce qu'il trouve dans un rapport texte. Les problèmes sont marqués [!] et repris en haut.

Utilisation

  1. Tapez DIAG (ou cliquez Diagnostics dans le groupe de fonctions Dépannage du ruban). Le rapport s'ouvre dans votre éditeur de texte.
  2. Lisez les problèmes en haut : chacun dit ce qui ne va pas et, la plupart du temps, quoi faire.
  3. Pour obtenir de l'aide, répondez Open issue : votre navigateur ouvre un nouveau ticket pour le développeur de DynALisp, son résumé rempli, et le dossier du zip de votre rapport. Décrivez ce qui s'est passé, glissez le zip dans le ticket, puis envoyez-le (voir Envoyer un rapport).
  4. Pour vérifier une partie rapidement, lancez sa commande seule (DIAG-DWG pour le dessin...) : les commandes ci-dessous.

Envoyer un rapport

  • DIAG met le rapport, vos paramètres DynALisp et vos copies des fichiers de données dans un dossier DynALisp Report <date> de votre dossier temporaire, et le compresse.
  • Open issue ouvre le nouveau ticket dans votre navigateur et le dossier du zip; Close garde le rapport où il est.
  • Un ticket GitHub est public : lisez le rapport avant de l'envoyer. Le rapport ne contient jamais votre dossier de profil, votre nom d'utilisateur ni le nom de votre ordinateur : ils sont remplacés par %USERPROFILE%, %USERNAME% et %COMPUTERNAME%. Vos copies des fichiers de données (préréglages, alias, clés de calque...) sont envoyées telles quelles. Le dessin lui-même n'est jamais envoyé.
  • L'envoyer demande un compte GitHub; sans compte, envoyez le zip par courriel.

Trouver ce qui ralentit AutoCAD

Pst-DiagnosticsReactorEvents (DIAG-EVENTS) compte les événements que le dessin envoie aux réacteurs : lancez-la, travaillez de la façon lente pendant environ 20 secondes (zoom, panoramique, dessin), puis lancez-la de nouveau. Le rapport liste chaque événement (un objet ajouté ou modifié, une commande lancée, une variable système modifiée) et son compte. Les réacteurs DynALisp ne s'exécutent que sur ces événements : quand aucun n'est compté pendant un zoom ou un panoramique lent, ce ne sont pas les réacteurs qui ralentissent. Elle demande que les réacteurs DynALisp soient activés (Dyl-Settings).

La partie Drawing chronomètre une régénération du dessin : lancez DIAG-DWG, changez une chose (la table d'ordre de tracé supprimée avec DO-RESET, les réacteurs désactivés et le dessin rouvert...), relancez-la et comparez.

Limites connues

  • Les programmes compilés des autres applications (.fas, .vlx, .dll) ne peuvent pas être lus : seul leur nom est listé, pas les commandes qu'ils définissent.
  • La partie du démarrage est celle du dessin où le rapport est fait; Dyl-Reload l'enregistre à nouveau.
  • Les types d'objets sont comptés jusqu'à 100 000 objets; au-delà, seul leur total est donné.

Noms des commandes et alias

Chaque programme a une commande principale qui commence par Dyl-. Les noms courts sont ses alias : ils lancent la même commande, et s'ajoutent, se renomment ou se retirent dans Dyl-Suite (enregistrés dans Resources\Aliases.csv).
