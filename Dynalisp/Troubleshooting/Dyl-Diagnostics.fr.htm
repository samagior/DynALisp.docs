Diagnostics

Syntaxe DYL-DIAGNOSTICS
Fichier source Modules\Dynalisp\Apps\Troubleshooting\Dyl-Diagnostics.lsp, son compte des événements dans Modules\Dynalisp\Reactor\Dyl-Diagnostics.lsp
Requis AutoCAD pour Windows (PowerShell pour compresser le rapport, un compte GitHub pour l'envoyer)
Licence Licence publique générale GNU v3

Description

Trouve pourquoi DynALisp, ou AutoCAD avec lui, ne fonctionne pas comme il le devrait. Il lit comment DynALisp est installé et démarré, l'AutoCAD en cours et ce qu'il charge d'autre, les paramètres et fichiers de DynALisp, ses réacteurs et le dessin courant, et écrit ce qu'il trouve dans un rapport texte qui s'ouvre dans votre éditeur de texte. Les problèmes trouvés sont marqués [!] et listés de nouveau en haut du rapport.

Dyl-Diagnostics (le bouton Diagnostics du groupe de fonctions Dépannage) écrit le rapport complet, avec vos paramètres et fichiers, et offre de l'envoyer au développeur de DynALisp dans un ticket GitHub. Chaque partie du rapport est aussi une commande propre, pour vérifier une chose rapidement.

Fonctionnement

Chaque partie du rapport vérifie une chose :

  • DynALisp : la version installée et la dernière version publiée (quand Dyl-Info l'a vérifiée), un clone git (sa branche et son commit) ou le programme d'installation, le dossier de DynALisp, une autre copie de DynALisp installée, le menu DynALisp, les paramètres en attente d'importation et vos fichiers. Puis le démarrage du dessin : sa durée, les commandes et alias définis, ses avertissements, les fichiers Remote et Reactor qui n'ont pas pu se charger et les plus lents, et les fichiers Lisp de chaque module.
  • AutoCAD : le produit et sa version, Windows, les profils, les variables système qui changent la façon dont les programmes se chargent et s'exécutent (SECURELOAD, NOMUTT, FILEDIA...), le chemin de recherche des fichiers de support (dossiers manquants ou répétés), les emplacements approuvés, acad.lsp, acaddoc.lsp et acad.pgp, les applications ARX et .NET chargées, les menus chargés, les paquets d'applications installés et la suite de démarrage d'AutoCAD (APPLOAD).
  • Conflicts : lit les fichiers Lisp des autres programmes que charge AutoCAD (acad.lsp, acaddoc.lsp, la suite de démarrage d'AutoCAD, les autres paquets d'applications et les dossiers de support hors d'AutoCAD lui-même, 300 fichiers au plus). Un fichier qui définit S::STARTUP avec defun (le démarrage de DynALisp risque de ne pas s'exécuter), ou une commande nommée comme une commande ou un alias de DynALisp, est un problème; un fichier qui retire des commandes AutoCAD ou crée des réacteurs est noté. Puis les alias de acad.pgp qui portent le nom d'une commande DynALisp activée ou d'un alias défini (l'un masque l'autre : renommez celui de DynALisp), les alias DynALisp non définis parce que leur nom est pris, et les réacteurs d'autres programmes dans le dessin.
  • Startup Suite : les commandes activées par module, les fichiers manquants de la suite de démarrage, les commandes activées mais non définies, une commande dans deux fichiers, les commandes principales sans page de docs, et les alias d'une commande qui n'est ni dans la suite de démarrage ni un préréglage personnalisé (restés d'une commande retirée ou renommée : retirez-les dans Dyl-Suite).
  • Settings : chaque paramètre Dynalisp*, vos fichiers (le dossier User, ceux dont le fichier par défaut est plus récent après une mise à jour), et chaque fichier de données que lit DynALisp (CSV) : un fichier illisible, les rangées qui n'ont pas les champs de leur en-tête, et le temps pour les lire tous.
  • Reactors : les paramètres des réacteurs, chaque réacteur activé a son réacteur dans le dessin (une fois), un compte de commandes bloqué ou des objets qui s'accumulent, et chaque réacteur du dessin.
  • Drawing : le fichier, ses unités et échelles, la phase active et le préréglage d'ordre de tracé, les objets et les entrées d'ordre de tracé de chaque espace, les calques, les blocs et les xréfs (introuvables ou non chargées), les types d'objets (objets proxy notés), les révisions de son projet (ses fichiers et les cartouches des présentations qui ont des révisions, voir Revisions) et le temps pour le régénérer.

Une partie lancée seule est écrite dans %TEMP%\DynALisp Diagnostics\<part>.txt et s'ouvre dans votre éditeur de texte.

Envoyer un rapport

Dyl-Diagnostics écrit chaque partie dans un dossier DynALisp Report <date> de %TEMP%, avec :

  • Report.txt : le rapport, qui s'ouvre dans votre éditeur de texte;
  • DynALisp-Settings.txt : vos paramètres DynALisp, tels que les écrit Export settings de Dyl-UserFiles;
  • User : vos copies des fichiers de données (préréglages, alias, clés de calque...).

Le dossier est compressé à côté de lui. La question Send it to the DynALisp developer in a GitHub issue? ouvre alors, avec Open issue, un nouveau ticket du dépôt des versions de DynALisp dans votre navigateur, son titre et son résumé remplis, et le dossier du zip avec le zip sélectionné : décrivez ce qui s'est passé, glissez le zip dans le ticket, puis Submit new issue. Close laisse le rapport où il est.

Un ticket GitHub est public : lisez le rapport avant de l'envoyer. Le rapport et le fichier des paramètres ne contiennent jamais votre dossier de profil, votre nom d'utilisateur ni le nom de votre ordinateur : ils sont remplacés par %USERPROFILE%, %USERNAME% et %COMPUTERNAME%. Les fichiers du dossier User sont envoyés tels quels. Le dessin lui-même n'est jamais envoyé, seulement ce que le rapport en dit.

Trouver ce qui ralentit AutoCAD

Pst-DiagnosticsReactorEvents (DIAG-EVENTS) compte les événements que le dessin envoie aux réacteurs : lancez-la, travaillez de la façon lente pendant environ 20 secondes (zoom, panoramique, dessin), puis lancez-la de nouveau. Le rapport liste chaque événement (un objet ajouté ou modifié, une commande lancée, une variable système modifiée) et son compte. Les réacteurs DynALisp ne s'exécutent que sur ces événements : quand aucun n'est compté pendant un zoom ou un panoramique lent, ce ne sont pas les réacteurs qui ralentissent. Elle demande que les réacteurs DynALisp soient activés (Dyl-Settings).

La partie Drawing chronomètre une régénération du dessin : lancez DIAG-DWG, changez une chose (la table d'ordre de tracé supprimée avec DO-RESET, les réacteurs désactivés et le dessin rouvert...), relancez-la et comparez.

Limites connues

  • Les programmes compilés d'autres applications (.fas, .vlx, .dll) ne peuvent pas être lus : seul leur nom est listé, pas les commandes qu'ils définissent.
  • Les données du démarrage (sa durée, ses avertissements et erreurs de chargement) sont celles du dessin où le rapport est fait; Dyl-Reload les enregistre de nouveau.
  • Les types d'objets sont comptés jusqu'à 100 000 objets; au-delà, seul leur total est donné.
  • Envoyer le rapport demande un compte GitHub; sans compte, envoyez le zip par courriel.
