ENFR

Import Layer Filters

Function Syntax LFIMP, LFLIST, IMPORTLAYERFILTER
Source File Modules\Dynalisp\Apps\Layer\Dyl-LayerImportFiltersFromDwg.lsp
Requires AutoCAD for Windows (ActiveX / Visual LISP) with ObjectDBX
Licence GNU General Public License v3

Program Description

Copies layer property filters (with their nested property filters) from another drawing, template or standards file into the current drawing. The source file is read in the background and is never modified. Layers themselves are not imported, only the filter definitions.

Commands

CommandNameDescription
LFIMPImport Layer FiltersImports the layer filters of another drawing into the current drawing.
LFLISTList Layer FiltersLists the layer filter tree of the current drawing at the command line.
IMPORTLAYERFILTERImport Layer Filters (Alias)Alias of LFIMP that imports the layer filters of another drawing.

How It Works

LFIMP / IMPORTLAYERFILTER

  1. Pick the source file (.dwg, .dwt or .dws). The current drawing itself is refused.
  2. The source is opened through ObjectDBX (or used directly if it is already open), its filter tree is read and the source is released right away.
  3. The source filter tree is printed at the command line. At Filters to import (name or wildcard, comma-separated) <*>: type names or wildcards of top-level filters, or press Enter for all of them.
  4. Names already used anywhere in the current filter tree are listed, and you choose Overwrite (replace the existing filter and its children), Skip (default) or Rename (import with a _1, _2 … suffix).
  5. The Layer Properties Manager is closed if it is open, so it cannot overwrite the result.
  6. The filters are written in one UNDO group and a report gives the number of filters imported, overwritten, renamed, skipped, not importable (group filters) and failed.

LFLIST

Prints the filter tree of the current drawing at the command line, with indentation for nested filters.

Known Limitations

  • Group filters are not imported (they refer to layers by handle, which only exist in the source); anything nested under a group filter is skipped too.
  • Drawings that only contain pre-2005 layer filters must be opened and saved in a recent AutoCAD first.

Bundled program notes 
;;; ==========================================================================
;;; ImportLayerFilters.lsp
;;;
;;; Imports layer property filters from a selected source drawing into the
;;; current drawing.
;;;
;;; Scope:
;;;   - Layer property filters (AcLyLayerFilter), including their nested
;;;     property filters (hierarchy is preserved).
;;;   - Layer group filters (AcLyLayerGroup) are NOT imported: they reference
;;;     layers by handle, which only make sense in the source drawing. Anything
;;;     nested under a group filter is therefore skipped as well.
;;;   - Layers themselves are NOT imported, only the filter definitions.
;;;   - The source drawing is never modified.
;;;
;;; Commands:
;;;   LFIMP              - import filters from a source drawing
;;;   IMPORTLAYERFILTER  - alias of LFIMP
;;;   LFLIST             - list the filter tree of the current drawing
;;;
;;; Storage (undocumented by Autodesk, observed):
;;;   Layer table > extension dictionary > ACLYDICTIONARY
;;;     XRECORD: (1 . "AcLyLayerFilter") (90 . 1) (300 . name) (301 . expr)
;;;   Nested filters: extension dictionary of the parent XRECORD
;;;     > ACLYDICTIONARY > XRECORD ...
;;;   Data is copied as-is (minus pointers), so any extra group codes used
;;;   by a given AutoCAD version are preserved.
;;;
;;; Duplicate names (checked against the whole current filter tree):
;;;   Overwrite - the existing filter (and its nested filters) is deleted,
;;;               then replaced by the source filter.
;;;   Skip      - the source filter (and its nested filters) is not imported.
;;;   Rename    - the source filter is imported with a _1, _2, ... suffix.
;;;
;;; Notes:
;;;   The source is read through ObjectDBX, or directly if the drawing is
;;;   already open in the session.
;;;   The Layer Properties Manager is closed before writing: if left open,
;;;   it could rewrite the filter tree from its in-memory copy and wipe out
;;;   the imported filters.
;;;   The operation is recorded as a single UNDO group.
;;; ==========================================================================
