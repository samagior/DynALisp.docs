Making A Module

The LeeMac module is the sample module of DynALisp: it shows, with over 100 programs by Lee Mac, how a collection of existing AutoLISP code becomes a DynALisp module, and it is the model for a module of your own. This page follows its parts. What the programs do and how to use them is in the User Guide; the rules every module follows are in the conventions.

The programs and their descriptions are the work of Lee Mac (www.lee-mac.com), who keeps all the credit for them. Their files keep their author and their licence (LEE-MAC-LICENCE.md, Lee Mac licence).

The Folders

A module is a folder of Contents\Modules. DynALisp loads and indexes every one the same way, so a new folder is all a module needs to start:

AppsOne Lisp file per program, in a group folder: Apps\General, Apps\Mathematical, Apps\Novelty, Apps\Utilities. A file is named exactly as its main command (LM-AddObjectsToBlock.lsp).
RemoteThe code every program shares, loaded on demand, once in a drawing, just before the first program of the module loads (Dyl:LibsLoad): Remote\LM-Sub.lsp, the Lee Mac subfunctions (over 300), each with the Remote>> prefix.
DocsThe User Guide: one page per program, in the same group folder as its file (Docs\General\LM-AddObjectsToBlock.htm), its pictures in images, and index.htm.
DevDocsThe developer docs: this page. A module of your own gets one page per program here, as the Dynalisp module does.

A module can also have Res (its data files and dialogs) and Reactor (its reactors, loaded only while the DynALisp reactors are on): the LeeMac module needs neither.

A Program File

  1. The heading – the GPL notice of DynALisp, the line saying the author's licence applies on top of it, the author and the date of the original, and the list of the changes made to integrate it. A file kept as an exact copy of the original says so: no renaming, no reformatting, no code added or removed, only the minor fixes it lists.
  2. The main command – one per file, c:LM-<Name>, named after what it does, in PascalCase and spelled out (LM-AddObjectsToBlock, not ADDTOBLOCK).
  3. The child commands – its presets and variants, c:Pst-<Name>. Each program has one that opens its original help page: c:Pst-2DProjectionHelp runs (startapp "explorer" "http://www.lee-mac.com/2dprojection.html").
  4. Two comment lines above each command – its name, then a one-line description: 
    ;; Add Objects To Block
;; Adds the selected objects to the definition of a picked block.

(defun c:LM-AddObjectsToBlock (/ *error* bln bnl btr def ent enx idx lst sel tmp)
    Dyl-SuiteUpdate reads them (Dyl:SuiteParse and Dyl:SuiteFlush of dynalisp.mnl: the token after (defun that starts with C:, and the last two comment lines before it) to write the row of the command.
  5. Nothing runs when the file loads – the original code that ran on load is removed: an App turned on is only autoloaded, and its functions are defined once one of its commands has run.

The Startup Suite

Dyl-SuiteUpdate scans the Apps files of every module and writes one row per command in Resources\StartupSuite.csv (your copy in User):

Load;Command;Name;Description;File;Module;Group;Duplicate;Path
1;C:LM-2DPROJECTION;2D Projection;Projects a selection of planar objects from one reference frame to another.;LM-2DProjection.lsp;LeeMac;General;;LeeMac\Apps\General\LM-2DProjection.lsp

From that index, Dyl-Suite turns each file on or off (the Load column), and DynALisp autoloads the files turned on: their commands are known at startup, the file is loaded the first time one runs. A child is shown under its main command ([+]), as the commands of the same file.

Aliases

The original names of a program are its short names, kept as aliases in Resources\Aliases.csv, never as extra code:

Alias;Command
C:ADDTOBLOCK;C:LM-ADDOBJECTSTOBLOCK

An alias never takes the name of a command of AutoCAD, of its Express Tools or of acad.pgp: Dyl-Suite refuses it, and an original name that is taken gets another alias (TXTCOUNT for Lee Mac's TCOUNT, ACL for his CL).

Shared Subfunctions

A subfunction used by several programs is loaded once, before the first program of the module runs, from Remote\LM-Sub.lsp, as Remote>>LM:<name>. A program that keeps its own local copy stays an exact copy of the original; a new program calls the remote one. In VS Code, the snippets LM-LocalSub and LM-RemoteSub insert a subfunction either way (.vscode\lmsnippets.py writes them from LM-Sub.lsp).

The Docs

  • A User Guide page per program, named as its file (Docs\General\LM-2DProjection.htm), found by Dyl-Suite from the file of the command. A program without a page of its own opens the index of its group, then of the module.
  • Each page of the LeeMac module is a copy of Lee Mac's help page, and begins with a note saying it is delivered for consistency purposes only, crediting Lee Mac and linking to the original page. Installer\Docs\BuildDocs.py reports a page without it.
  • BuildDocs.py writes the language switch and the list of the pages of the website; the website is built and published on every push to main (see the developer home).

A Module Of Your Own

  1. Make a folder in Contents\Modules with Apps\<Group>; to keep it out of git, add it to .gitignore as MyTools is.
  2. Put one program per Lisp file, its main command named after the file, its two comment lines above each command, nothing run on load.
  3. Run Dyl-SuiteUpdate, then turn the files on in Dyl-Suite and give the commands their aliases there.
  4. Add a docs page per program in Docs\<Group>: Dyl-Suite opens it from your computer (the website has only the modules of the repository).
