Months

The developer docs of the Months window of the Simulation: its files and how its code works. What it does and how to use it are in its User Guide page.

Source FilesRes\Dyl-SimulationMonths.xaml (the window, shown by DynALisp.Windows.dll), Res\Dyl-Simulation.xaml (its open button clm), Modules\Dynalisp\Apps\Analysis\Dyl-Simulation.lsp (Dyl:SimClimRow, Dyl:SimClimOf, Dyl:SimMonthTexts)
DataThe columns 6 to 29 of Res\Climates.csv (its user copy): T01 to T12, the temperature of each month in C, then RH01 to RH12, its relative humidity in %, January first, empty when not known

The Window

The Simulation window opens it itself, with no call to the Lisp: the open button clm beside Months has dyl:Win.Open="Dyl-SimulationMonths.xaml" and dyl:Win.Columns="mt1:6,...,mt12:17,mh1:18,...,mh12:29", so the window edits those columns of the row shown of the climates list cl (a list of rows, Engine\Rows.cs) as its keys, and its OK gives them to every row selected. The columns are the values as shown (Dyl:SimClimRow: in F in an imperial drawing, *sim:climdata*), the units following sim.imp of the session; Dyl:SimClimOf stores them back in SI when the climates are saved, a value shown and not changed kept as it was in the file (the columns 30 to 57 of the row hold the values of the file, 58 to 85 those shown when the window opened).

Each box is checked by dyl:Win.Check: empty;number for a temperature, empty;number;min=0;max=100 for a humidity. That a climate has all twelve months or none is checked by the plugin when the monthly balance runs (PartMonths), not by the window, so a climate can be typed over several sessions.

The plugin gets the months by Dyl:SimMonthTexts, a text "id|t1|...|t12|rh1|...|rh12" for each climate that has one (see Simulation).
