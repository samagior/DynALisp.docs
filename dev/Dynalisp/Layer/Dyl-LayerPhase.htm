Layer Phase

The developer docs of Layer Phase: its files and how its code works. What it does and how to use it are in its User Guide page.

Source Files Modules\Dynalisp\Remote\Dyl-LayerPhase.lsp (the phases and the active phase), Modules\Dynalisp\Reactor\Dyl-LayerPhase.lsp (auto-phase), Modules\Dynalisp\Apps\Layer\Dyl-LayerPhase.lsp (the commands and the Layer Phases window)
Data Modules\Dynalisp\Res\AEC\Standard\Phase.csv (the phases), the dyl-layer dictionary of each drawing (its active phase), the user settings DynalispPhaseAuto and DynalispPhaseSkip
Uses Layer Keys (Remote>>Dyl:LayerKeyPhased, Remote>>Dyl:LayerKeyKeepColor, Remote>>Dyl:LayerKeyDialog), the ribbon plugin (Dyl:RibbonPhase), the reactor helpers of dynalisp.mnl

The Three Files

The work is split by when it must be loaded, as the Folders and Reactors conventions ask:

  1. Remote – loaded at startup in every drawing, before the Apps: the phase list, the names, the active phase and its setters. Every other program (Layer Keys, Quick Draw, Layer Transfer, the ribbon) calls these functions, so they must exist before any command runs. The file ends with (Remote>>Dyl:PhaseStatus), so each drawing opened shows its phase.
  2. Reactor – loaded after the Remote files, only while DynalispReactors is on (Dyl:load skips the Reactor folders otherwise): the auto-phase reactors. Off, the file is not loaded and nothing of it exists; the code of the other files checks (if Reactor>>Dyl:PhaseReactors ...) first.
  3. Apps – autoloaded, defined when one of its commands runs: Dyl-LayerPhase (the window) and its Pst-Phase* children, run by the PH-* aliases of Resources\Aliases.csv.

The Phases

  • Remote>>Dyl:PhaseList returns ((code description) ...). It reads Phase.csv through Dyl:UserFile (the user's copy first), with Remote>>LM:csv->lst and the separator of its header (;, tab or ,). A row counts when its first field is a single character valid in a name (snvalid), once per code, upper case.
  • The description is the 6th column, Description, or the column Description.<code> of the language of the AutoCAD installed (Dyl:LangAcad, never the docs language), found by its name in the header. The file is opened as UTF-8 ((open f "r" "utf8")); an AutoCAD that cannot (older than 2021) opens it in the code page of Windows and keeps the English column.
  • Without the file, or while Remote>>LM:csv->lst is not defined (it is in Dyl-Basics.lsp, which loads before Dyl-LayerPhase.lsp), the list is *ph:defaults*, the eleven NCS phases. Dyl:load calls Remote>>Dyl:PhaseStatus again once every Remote file is loaded.
  • The file is read again on every call: the functions below take the list as their codes argument, read once per operation by their caller.

Layer Names

  • (Remote>>Dyl:PhaseOf lay codes) – the phase of a name: its last character when the name matches *?-? and that character is a code of the list ("A-Wall-Full-E" → "E"), else nil.
  • (Remote>>Dyl:PhaseBase lay codes) – the name without its phase ("A-Wall-Full").
  • (Remote>>Dyl:PhaseTarget lay code codes bases) – the layer an object on lay goes to in phase code, nil when it stays: never for *ph:never* (0, DEFPOINTS, any name with |, the xref layers); a phased name takes the new code in place of its own; a name of bases, the layers of the layer keys (Remote>>Dyl:LayerKeyPhased, upper case), gets -code added; any other name stays.
  • (Remote>>Dyl:PhaseColor aci from to) – the color of a layer moved from one phase to another, the rule of Layer Transfer: to D, 2 followed by the last digit of the color (7 → 27); to E, 20 followed by it (7 → 207); from D or E to another phase, the last digit alone; otherwise the color is kept. A result outside 1–255 gives 7.
  • (Remote>>Dyl:PhaseMake src new from to) – creates new when the drawing does not have it, from src: linetype, lineweight, plot and description of src, and the color of Remote>>Dyl:LayerKeyKeepColor when the name (without its phase) is the layer of a key that keeps its color in every phase, else PhaseColor. Returns T when the layer exists afterwards.
  • (Remote>>Dyl:PhaseLayer lay code) – the two above together: the layer of lay in phase code, created when missing; lay itself when it is not phased or code is nil.

The Active Phase

  1. It is kept in the drawing, (vlax-ldata-get "dyl-layer" "phase"), so each drawing has its own and keeps it when saved; "" means none. Remote>>Dyl:PhaseGet returns the code or nil.
  2. (Remote>>Dyl:PhaseSet code) writes it (nil writes ""), moves CLAYER to (Remote>>Dyl:PhaseLayer (getvar "CLAYER") code) when that is another layer, prints the new phase (and auto-phase off when it does not run), then calls Remote>>Dyl:PhaseStatus.
  3. Every setter goes through it: the aliases (Pst-PhaseExisting … Pst-PhaseNone, each (ph:switch code)), a double-click in the window, and the Phase drop-down of the ribbon, whose plugin runs (Remote>>Dyl:PhaseSet "N") when the user picks an item (PhaseCombos.cs).
  4. Pst-PhaseNext cycles through ph:cycle: E, D, N, F, then the other phases that have layers in the drawing, in the order of Phase.csv; after the last one, the first again.
  5. The layer keys read it too: while auto-phase is on, Remote>>Dyl:LayerKeyLayer gives the layer of a key in the active phase.

The Status Bar And The Ribbon

Remote>>Dyl:PhaseStatus shows the state in both places, and runs after every change of the phase or of auto-phase, when a drawing becomes current and when DynALisp loads:

  • Status bar – MODEMACRO is set to Phase: N - New Work [Auto] (or Phase: none [Auto], or ""), only when it is empty or already starts with Phase: : a MODEMACRO set by something else is left alone.
  • Ribbon – when the plugin is loaded (AutoCAD 2025 and later), (Dyl:RibbonPhase code auto reactors phases): the active phase (or nil), DynalispPhaseAuto, DynalispReactors and the flat list ("E" "Existing To Remain" "D" ...). The plugin only records the state; it updates its drop-downs when AutoCAD is idle (see the Ribbon convention), and reads the translated descriptions of Phase.csv itself.

Auto-phase

A user setting, DynalispPhaseAuto ("1" on, off on a new installation), the same in every drawing. Remote>>Dyl:PhaseAuto-p reads it; Remote>>Dyl:PhaseAutoOn-p is T when it is on and the DynALisp reactors are on too, the only case where it runs. (Remote>>Dyl:PhaseAutoSet on) writes it, makes or removes the reactors of the drawing (Reactor>>Dyl:PhaseReactors, when the Reactor file is loaded) and updates the status; it is called by PH-AUTO, the Auto-phase drop-down and the Auto-phase new objects toggle of Dyl-Settings.

The reactors

Reactor>>Dyl:PhaseReactors removes the reactors of the file and resets its variables, then, when auto-phase and the reactors are on, makes two reactors, each through Dyl:ReactorLocal (only the drawing in front acts):

*ph:append*An acdb reactor, :vlr-objectAppended → Reactor>>Dyl:PhaseOnAppend. Made off: Reactor>>Dyl:PhaseWatch adds it only while a command or a Lisp command runs. Objects are also added with no command running (the Project Navigator palette of AutoCAD Architecture, as the first drawing opens), and a Lisp call for each of them froze AutoCAD.
editor reactor:vlr-commandWillStart → PhaseOnStart; :vlr-commandEnded, Cancelled, Failed → PhaseOnEnd; :vlr-lispWillStart → PhaseOnLisp; :vlr-lispEnded, Cancelled → PhaseOnLispEnd.

One command, step by step

  1. A command starts (PhaseOnStart) – when no other command runs (Dyl:CmdTop-p of dynalisp.mnl), *ph:depth* goes back to 0, so a count left above 0 by a command whose end was never seen cannot stop auto-phase. At depth 0, *ph:off* is set when the command matches the skip pattern (Reactor>>Dyl:PhaseSkip: DynalispPhaseSkip, else *ph:skip*: UNDO, TRIM, BREAK, PASTE*, XBIND…). The depth goes up by one (a transparent 'ZOOM runs inside another command) and the append reactor is turned on.
  2. Objects are added (PhaseOnAppend) – only collected: the entity name goes to *ph:new*, unless the command is skipped (*ph:off*) or the objects are being moved (*ph:busy*: the phase layers created then are not collected). An object cannot be changed while it is being added.
  3. The command ends (PhaseOnEnd, also when it is cancelled or fails) – the depth goes down; at 0, *ph:off* is cleared and, unless a Lisp command is running, the append reactor is turned off and Reactor>>Dyl:PhaseRunSafe runs.
  4. A Lisp command (PhaseOnLisp, PhaseOnLispEnd) – *ph:lisp* keeps the objects of every command it runs until it ends; then the variables are reset, the append reactor turned off, and the objects moved at once.
  5. The objects move (Reactor>>Dyl:PhaseRun, through PhaseRunSafe, which catches any error so the next commands never stop) – with an active phase: *ph:busy* on, the phase list and the layer key layers read once, then for each object still there, not a viewport, owned by model space or a layout (Reactor>>Dyl:PhaseInSpace-p: never a block definition): Reactor>>Dyl:PhaseMove takes its target (PhaseTarget), makes the layer (PhaseMake) and puts the object on it. The attributes of a block reference move the same way. A target layer that is off (negative color) or frozen (bit 1 of code 70) is listed, and the command line gives the count and those layers.

Other drawings, and turning off

  • Every drawing has a document reactor, *ph:docreactor* (:vlr-documentBecameCurrent → Reactor>>Dyl:PhaseOnDoc), made again on each load of the file (Dyl-Reload) so it always runs the current functions. When its drawing becomes current, it makes or removes the auto-phase reactors to follow a setting changed in another drawing, and shows the drawing's own phase. When the DynALisp reactors were turned off elsewhere, it calls Dyl:ReactorsStop instead.
  • The file registers Reactor>>Dyl:PhaseStop with Dyl:ReactorsAdd: Dyl:ReactorsStop runs it to remove all its reactors at once.

The Layer Phases Window

  • c:Dyl-LayerPhase writes the window to a temporary DCL file (ph:dcl, deleted when it closes) and works on its locals: ph:codes (the phase list after ("" "Unphased")), ph:sel (the codes selected), ph:stat and ph:regen.
  • ph:stats counts, per phase, the layers (tblnext), the layers shown (positive color and not frozen) and the objects ((ssget "_X" '((8 . "*?-E")))); the objects of Unphased are all the objects less the phased ones. The visibility is Shown, Hidden, Partial or - (no layer).
  • ph:show turns the layers of the phases selected on and thaws them, or off and freezes them (the current layer is only turned off); xref layers included. Isolate phase hides every other phase but Unphased. The drawing is regenerated at once; when it cannot be while the window is open, ph:regen regenerates it when the window closes.
  • Layer keys Editor closes the window with code 3, runs (Remote>>Dyl:LayerKeyDialog nil), and the loop opens the window again.

Using Phases In An App

CallReturns
(Remote>>Dyl:PhaseGet)The active phase code ("N"), nil when there is none.
(Remote>>Dyl:PhaseSet "N")Sets the active phase (nil: none), moves the current layer, updates the status.
(Remote>>Dyl:PhaseLayer "A-Wall-Full-E" "N")"A-Wall-Full-N", created when missing.
(Remote>>Dyl:PhaseList)(("E" "Existing To Remain") ...): pass it as codes to PhaseOf, PhaseBase, PhaseTarget.
(Remote>>Dyl:PhaseAutoOn-p)T when auto-phase runs (on, and the reactors on).
(Remote>>Dyl:LayerKeyLayer "THIN")The layer of a layer key, in the active phase while auto-phase is on.

An object a Lisp command of an App creates moves to the active phase when the command ends, as any other: an App has nothing to do for auto-phase. To draw on a phase other than the active one, take the layer with PhaseLayer.

Diagnostics

Dyl-Diagnostics (Diagnostics) reports, in its Reactors section, DynalispPhaseAuto, whether the drawing has its one database reactor (none while it is on, or one while the reactors are off, is a problem), *ph:depth* and the objects waiting in *ph:new* (a depth above 0 with no command running is a count stuck); and the active phase in its Drawing section.

Known Limitations

  • The objects are moved in a step of their own after the command, so U undoes the move first.
  • UNDO restores the dyl-layer dictionary but no reactor sees it: the status bar and the drop-down show the restored phase only at the next PhaseStatus.
  • Remote>>Dyl:PhaseList reads Phase.csv on every call (each status update, each move of objects).
  • The window is written from Lisp strings to a temporary file; the Folders convention keeps the dialogs in Res.
