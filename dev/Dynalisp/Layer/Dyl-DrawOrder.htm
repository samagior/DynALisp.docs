Draw Order

The developer docs of Draw Order: its files and how its code works. What it does and how to use it are in its User Guide page.

Source FilesModules\Dynalisp\Remote\Dyl-DrawOrder.lsp (the presets, the levels and the restacking, loaded at startup), Modules\Dynalisp\Reactor\Dyl-DrawOrder.lsp (auto draw order, while the reactors are on), Modules\Dynalisp\Apps\Layer\Dyl-DrawOrder.lsp (the window and the commands). Based on Layer Draw Order (LDOrder) by Lee Mac.
DataRes\DrawOrder\<preset>.csv (one file per preset, the folder copied to User when saved); the preset of the drawing (saved in it); the user settings DynalispDrawOrderAuto, DynalispDrawOrderPreset (the preferred preset), DynalispDrawOrderSkip, DynalispDrawOrderRefresh

The Rules

A preset file has one rule per row:

Name;Level;Layers;Objects;Description;Order
Annotation;8;*-Anno,*-Anno-[~R]*;;Annotation layers;10
Hatch objects;-4;;HATCH;Hatches on any layer;20
  • A rule matches an object when its Layers (layer name wildcard) and its Objects (DXF type wildcard) both match, an empty cell matching anything. The object takes the level of the rule with the lowest Order among those that match (the first row on a tie), 0 when none matches.
  • Remote>>Dyl:DrawOrderRules reads the active preset (Remote>>Dyl:DrawOrderPreset: the one saved in the drawing, else the preferred one, else Default; *do:defaults* without any file). A file written before the Order column gets one from its levels, the highest first (Remote>>Dyl:DrawOrderFill), so its result does not change. Remote>>Dyl:DrawOrderParse turns the rows into rules, Remote>>Dyl:DrawOrderRule / DrawOrderOf give the level of an object.

How It Works

  1. Each level keeps the draw order of its own objects: restacking moves whole levels to the top (the lowest positive level first) or to the bottom (the highest negative level first) with the draw order table of the space.
  2. Auto draw order watches the objects added to the drawing and restacks when the command that created them ends, like auto-phase. Objects created by a Lisp command are restacked when the Lisp command ends.
  3. Only the new objects are moved, right below the lowest object of the levels that must stay above them: a new line goes under the annotation, a new hatch under the lines, a new text on the top level moves nothing. The levels already stacked are left alone. When the draw order cannot be read, the levels above or below the new objects are restacked instead.
  4. Each restack adds entries to the draw order table of the space, and a large table slows down panning and zooming. DO-REBUILD deletes the tables of model space, the layouts and the block definitions, then stacks the levels again from the creation order, as one undo step. The output prep step Rebuild the draw order (Dyl-PrepSuite, off by default) does the same before the commands it is checked for, in place of Apply the draw order. A DRAWORDER set by hand within a level is lost by a rebuild.
  5. The objects of model space, of the layouts and of the block definitions are restacked: a hatch inside a block goes below the lines of that block, like in the drawing. The levels are those of the objects in the block (often layer 0, so the rules by object type are the ones that apply). Auto draw order restacks a block definition when objects are added to it (BLOCK, BEDIT, REFEDIT...) and regenerates the drawing so its references show it. Xrefs and their blocks are never changed, nor the anonymous blocks AutoCAD makes again itself (dimensions, tables...); the ones of the dynamic blocks are restacked. Viewports are left out.
  6. The objects brought back by U, UNDO, REDO and OOPS are left where they are. The list can be replaced with the DynalispDrawOrderSkip environment variable, and the commands that restack the current space with DynalispDrawOrderRefresh, for example (setenv "DynalispDrawOrderRefresh" "LAYMCH,MATCHPROP,CHPROP").

Restacking, In The Code

  • Remote>>Dyl:DrawOrderTable gets the SortentsTable of a block (the extension dictionary of the space or of a block definition); Remote>>Dyl:DrawOrderSpace the block of a layout name.
  • (Remote>>Dyl:DrawOrderStack tab top bot rules) groups the objects of each level (Remote>>Dyl:DrawOrderLevels in a space, DrawOrderBlockLevels in a block) and moves each group with MoveToTop (the lowest positive level first) or MoveToBottom (the highest negative level first): every level keeps the order of its own objects.
  • Remote>>Dyl:DrawOrderApply stacks one space, or model space, every layout and every block of Remote>>Dyl:DrawOrderBlocks (not the xrefs, nor the anonymous blocks AutoCAD remakes itself, but the *U of dynamic blocks).
  • Remote>>Dyl:DrawOrderRebuild deletes the tables first, then stacks again from the creation order.
  • Remote>>Dyl:DrawOrderPlace, used by auto draw order, moves only the new objects: right below the lowest object of the levels that must stay above them (DrawOrderAbove, DrawOrderLowest), or the levels around them when the table cannot be read (DrawOrderBounds). DrawOrderPlaceSafe catches its errors.

Auto Draw Order

Reactor\Dyl-DrawOrder.lsp works as the auto-phase reactors of Layer Phase, with its own variables (*do:new*, *do:depth*, *do:lisp*, *do:off*, *do:busy*, *do:append* made only while a command runs) and one more: *do:ref*, set when a command of Reactor>>Dyl:DrawOrderRefresh ran, so that the current space is restacked when it ends. Reactor>>Dyl:DrawOrderRun finds the space of each new object (Reactor>>Dyl:DrawOrderSpaceOf, a block definition included) and places them, space by space. The output prep steps DRAWORDER and DRAWORDERCLEAN (Prep Drawing) call DrawOrderApply and DrawOrderRebuild.

Using The Draw Order In An App

  • (Remote>>Dyl:DrawOrderApply nil nil) – restacks model space, every layout and every block definition with the rules of the active preset, returns the number of objects moved.
  • (Remote>>Dyl:DrawOrderApply "Model" nil) – restacks one space, given by its layout name. The second argument can give other rules (see Remote>>Dyl:DrawOrderParse).
  • (Remote>>Dyl:DrawOrderRebuild nil nil) – deletes the draw order tables of model space, every layout and every block definition, then restacks them; a layout name in place of the first nil rebuilds one space.
  • (Remote>>Dyl:DrawOrderPreset) – returns the name of the active preset, (Remote>>Dyl:DrawOrderPresetSet "Details") saves another one in the drawing (nil: the drawing uses the preferred preset), (Remote>>Dyl:DrawOrderPresetDefault) returns the preferred preset.
  • (Remote>>Dyl:DrawOrderAutoSet T) – turns auto draw order on (nil: off).
