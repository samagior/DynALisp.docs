Layer Transfer

The developer docs of Layer Transfer: its files and how its code works. What it does and how to use it are in its User Guide page.

Source FilesModules\Dynalisp\Apps\Layer\Dyl-LayerTransfer.lsp; the ribbon drop-downs in Installer\Ribbon\Plugin\TransferCombos.cs
DataThe layers and the block definitions of the drawing; the values of the drop-downs from Res\AEC\Standard (Dd1.csv, Dd2.csv, Major.csv, Phase.csv)

How It Works

  1. Select objects. Objects whose layer contains the source field are pickable, and block references are always pickable so their content can be transferred.
  2. Each selected object is checked: its own layer, its attributes and, for blocks, every entity of the definition (nested blocks included) are tested. Objects with nothing to change are dropped.
  3. The target name of each source layer is computed (see rules below). A missing target layer is created with the linetype, lineweight, plot setting, description and transparency of the source, and a colour shifted for the phase: -D → 2 + last digit, -E → 20 + last digit, unphased from -D/-E → last digit only. A phase layer of a layer key (the target name without its phase, G-Detl-Exst-D → G-Detl-Exst, is the layer of that key) gets the color of its key in that phase instead: the phase color of the key color, or the key color itself when the key keeps it in every phase (Keep this color in every phase) or the transfer is to unphased.
  4. A target layer of a layer key that already exists is checked against its key (color in that phase, linetype, lineweight, plot), as when an App uses the key: when it differs, the same window lists the differences and asks whether to update it to its key, before the objects are moved (Yes / No, Remember my answer; see Layer Keys – Layers That Differ From Their Key).
  5. If a source layer is off, frozen or locked, an alert lists it and nothing is changed.
  6. In one UNDO group, objects and attributes are moved to their target layers. A block whose content changes is copied (through ObjectDBX, which keeps dynamic block data) to a new name – 2X6 → 2X6-N, 2X6-E → 2X6-N – the copy is transferred and the selected references are pointed to it, with their dynamic property values restored. A copy made by an earlier run is reused.

Name Rules

  • Phase – the suffix is replaced at the end of the name (A-Wall-E → A-Wall-D). A name ending with a 4-character field and no phase (A-Wall-Full) gets the new suffix appended. The Unphased commands remove the suffix.
  • Designator – the first occurrence of the discipline letter is replaced.
  • Major – the first occurrence after the designator is replaced (e.g. Detl ↔ Sect).
  • Minor – the first occurrence from the 8th character on is replaced (Line ↔ Hidd, stack numbers).
  • Level (the Transfer button of the ribbon and LTF) – the name is read as an NCS name: a discipline designator of 1 or 2 letters, a major group of 4 characters, minor groups of 4 characters (none or more) and an optional status of 1 character, divided by -. Only that level is replaced, so a designator transfer never touches the other levels. The layers with other names (0, Defpoints, the layers of the xrefs...) are left as they are.

The Code

  • A transfer – each child (c:Pst-TransferExistingToDemolition...) calls (Dyl-LayTransfer pattern new) with the part of the names to replace and its replacement. c:Dyl-LayerTransfer is Dyl:ChildPicker.
  • Names – Dyl-LayTransfer-Match tells a candidate layer (the rule of the selection filter); Dyl-LayTransfer-Ncs splits an NCS name into (discipline major (minor ...) status) (Dyl-LayTransfer-Split), nil for another name or an xref layer, the same rule as NcsName of TransferCombos.cs: change both together. Dyl-LayTransfer-Target and Dyl-LayTransfer-FieldTarget give the new name; a field transfer (the ribbon, Pst-TransferField) replaces one field of the NCS name.
  • Blocks – Dyl-LayTransfer-Scan finds the definitions with content to transfer (Dyl-LayTransfer-Check), Dyl-LayTransfer-CopyDef copies a definition under a new name (Dyl-LayTransfer-BlockName, through ObjectDBX), Dyl-LayTransfer-Convert transfers its content, and Dyl-LayTransfer-Swap points the selected references to it, keeping the values of a dynamic block.
  • Layers – Dyl-LayTransfer-Apply moves an object, its attributes and its content; a missing target layer is made from the source layer, its color derived from the source color (*src-clr): 2# to -D, 20# to -E, back to # when unphased, the color of its key for the layer of a layer key (the same rule as Remote>>Dyl:PhaseColor of Layer Phase, written again here). Objects on source layers that are off, locked or frozen are not moved: they are reported.
  • The ribbon – Pst-TransferField, the Transfer button, reads the choice of the drop-downs from the plugin ((if Dyl:RibbonTransfer ...)) and asks for the values when there is none.
