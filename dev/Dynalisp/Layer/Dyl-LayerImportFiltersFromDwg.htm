Import Layer Filters

The developer docs of Import Layer Filters: its files and how its code works. What it does and how to use it are in its User Guide page.

Source FilesModules\Dynalisp\Apps\Layer\Dyl-LayerImportFiltersFromDwg.lsp
Reads and writesThe ACLYDICTIONARY of the layer table of the source (through ObjectDBX) and of the current drawing

How It Works

LFIMP / IMPORTLAYERFILTER

  1. Pick the source file (.dwg, .dwt or .dws). The current drawing itself is refused.
  2. The source is opened through ObjectDBX (or used directly if it is already open), its filter tree is read and the source is released right away.
  3. The source filter tree is printed at the command line. At Filters to import (name or wildcard, comma-separated) <*>: type names or wildcards of top-level filters, or press Enter for all of them.
  4. Names already used anywhere in the current filter tree are listed, and you choose Overwrite (replace the existing filter and its children), Skip (default) or Rename (import with a _1, _2 … suffix).
  5. The Layer Properties Manager is closed if it is open, so it cannot overwrite the result.
  6. The filters are written in one UNDO group and a report gives the number of filters imported, overwritten, renamed, skipped, not importable (group filters) and failed.

LFLIST

Prints the filter tree of the current drawing at the command line, with indentation for nested filters.

The Code

  • Opening the source – lfi:open-source uses the document when the file is open in this AutoCAD, else opens it in ObjectDBX.AxDbDocument.<version> (released at once after the tree is read, never saved); lfi:has-legacy finds a drawing with only pre-2005 filters.
  • Reading the tree – lfi:get-filter-dict finds the filter dictionary, lfi:read-tree walks it into nodes (class name data children), the data ready for entmakex, lfi:xrec-data and lfi:clean-data keep the data of a filter without its handles; lfi:prop-p tells a property filter (importable) from a group filter (its layers are handles of the source).
  • Writing – lfi:import-node writes a node and its children with lfi:make-xrec under a free key (lfi:unique-key); a name taken is replaced (lfi:delete-node removes the old one and its children) or renamed (lfi:unique-name). lfi:dest-index lists every name of the destination tree, nested ones included.
  • c:Dyl-LayerImportFiltersFromDwg (LFIMP) runs it in one undo group, closes the Layer Properties Manager first (it writes its own copy of the tree when it closes), and prints the counts; c:Pst-ListLayerFilters (LFLIST) prints the tree with lfi:print-tree.
