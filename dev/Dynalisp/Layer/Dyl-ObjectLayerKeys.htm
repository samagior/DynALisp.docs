Object Layer Keys

The developer docs of Object Layer Keys: its files and how its code works. What it does and how to use it are in its User Guide page.

Source FilesModules\Dynalisp\Remote\Dyl-LayerKey.lsp (the kinds, their keys and the setting, Object layer keys region), Modules\Dynalisp\Reactor\Dyl-ObjectLayerKeys.lsp (the reactors), Modules\Dynalisp\Apps\Layer\Dyl-ObjectLayerKeys.lsp (the window)
DataModules\Dynalisp\Res\ObjectLayerKeys.csv (one row per kind: its id and its key, "": none; your copy under User); the user setting DynalispObjectKeys

The Kinds

*olk:objects* lists the kinds as (id label types commands key): the DXF types (a wcmatch pattern), the commands that make them (nil: any; a revision cloud is a polyline made by REVCLOUD), and the default key (an AEC key of *lk:aec*). (Remote>>Dyl:ObjectKeysKind type command) returns the first kind that matches. Remote>>Dyl:ObjectKeysRead reads the keys of the file, a kind it does not have getting its default; Remote>>Dyl:ObjectKeysSkip is *olk:skip* and the skip list of auto-phase.

How It Works

  1. While a command runs, the new objects are collected; when it ends, each one of a kind with a key goes to the layer of that key (created with the key properties when the drawing does not have it, thawed when frozen, see Layer Keys). A message gives their number.
  2. While auto-phase is on, the layer of the key is the one of the active phase (G-Anno-Dims-E).
  3. The objects made by a Lisp command are left as they are: the DynALisp tools (Quick Draw, Quick Shape...) put theirs on their own layer keys.
  4. Copies keep the layer of their original: the objects made by COPY, MIRROR, ARRAY, OFFSET, a grip copy, a paste, an insert, an explode and the other commands that edit or bring in objects (those of auto-phase) are left on their layer. Objects inside a block definition are never changed, nor the paper space viewport of a layout.
  5. From a reactor no window can open: a layer that differs from its key is checked the next time a tool uses the key (Layers That Differ From Their Key). An AEC layer override as shipped uses its own layer there (the layer key style of the drawing is read by a command, which cannot run from a reactor).
  6. The keys are saved to Modules\Dynalisp\Res\ObjectLayerKeys.csv (its copy under User): one row per kind, its id and its key. A kind missing from the file gets its default key.

The Reactors

Reactor\Dyl-ObjectLayerKeys.lsp works as the auto-phase reactors of Layer Phase: an append reactor (Reactor>>Dyl:ObjectKeysWatch, made only while a command or a Lisp command runs), the command and Lisp events, a count reset by Dyl:CmdTop-p, and Reactor>>Dyl:ObjectKeysRun when the outer command ends: each new object in model space or a layout (Reactor>>Dyl:ObjectKeysInSpace-p) whose kind has a key goes to Remote>>Dyl:LayerKeyLayer of its key. Its variables are *olk:new*, *olk:depth*...; Dyl-Diagnostics reports them with those of auto-phase.

The Window

Dyl:ObjectKeysDialog writes its DCL to a temporary file (Dyl:ObjectKeysDcl) and works on ol:lst (the keys of the kinds), ol:sel (the kinds selected), ol:keys (the keys of the popup, none first) and ol:lks (the layer keys). Dyl:ObjectKeysLayer shows the layer a key gives; Dyl:ObjectKeysReset sets the default of the kinds selected, or of all.
