System Variables

The developer docs of System Variables: its files and how its code works. What it does and how to use it are in its User Guide page.

Source FilesModules\Dynalisp\Remote\Dyl-SysVars.lsp (the profiles and their check in each drawing, loaded at startup), Modules\Dynalisp\Apps\Setup\Dyl-SysVars.lsp (the window), Modules\Dynalisp\Res\Dyl-SysVars.xaml, Dyl-SysVarsList.xaml (the list of every variable), Modules\Dynalisp\Res\Dyl-Name.xaml (the name of a profile)
DataRes\SysVars\<profile>.csv (one file per profile), Res\SysVarsProtected.csv, their copies under User; the user settings DynalispSysVarOn, DynalispSysVarProfile (the active profile) and DynalispSysVarStamp; the Express Tools list Express\sysvdlg.dat

The Profiles

How It Works

  • A value is read as the type of the current value of its variable: a whole number (PICKADD 2), a number (LTSCALE 1.5), a text, or a point written x,y or x,y,z.
  • Each drawing opened sets the protected variables and those of the active profile that differ, without marking the drawing as modified; the window shows what differs. A profile saved, or System variables turned on, in another drawing applies to the drawings already open when you switch to them, while Settings sync is on.
  • The profiles are the CSV files of Modules\Dynalisp\Res\SysVars (Variable;Value, one variable per row). Saved profiles go to User\Modules\Dynalisp\Res\SysVars (see Dyl-UserFiles). The Default profile is empty. The protected variables are Modules\Dynalisp\Res\SysVarsProtected.csv (Variable;Value, an empty value: protected only), saved to its copy under User.
  • Remote>>Dyl:SysVarDir is the folder read (the user copy when there is one, Dyl:UserDir), Remote>>Dyl:SysVarDirW the one written (the whole folder copied the first time, Dyl:UserDirW): profiles are added and deleted, so the folder is a user copy as a whole (User Files).
  • Remote>>Dyl:SysVarRead returns the rows of a profile, (("PICKADD" "2") ...), the names in upper case; Remote>>Dyl:SysVarKeep the protected rows.
  • Remote>>Dyl:SysVarValue turns a text into the type of the current value of its variable: the text itself, a whole number (refused when it has decimals), a real (distof), or a point of the same number of coordinates. nil means the value is not valid. Remote>>Dyl:SysVarText writes a value back (a real without its trailing zeros, a point as x,y).

Setting A Drawing, Step By Step

  1. Remote>>Dyl:SysVarApply runs as a startup step of each drawing (Dyl:StartupStep "System variables" in dynalisp.mnl, which also keeps the stamp in SV:synced); nothing is done while DynalispSysVarOn is off.
  2. Between acad-push-dbmod and acad-pop-dbmod (the drawing is not marked as modified), Remote>>Dyl:SysVarSetAll sets first the protected rows that have a value, then the rows of the active profile, its protected variables skipped.
  3. Remote>>Dyl:SysVarSet skips a variable that already has its value (Remote>>Dyl:SysVarSame-p: texts in any case, numbers and points with a fuzz of 1e-6), and sets the others in a vl-catch-all-apply: an unknown variable, a value not valid or a read-only variable is listed as not set.
  4. It returns a status line, Default: 3 set (PICKADD, ...), not set: ..., kept by the startup.
  5. A change saved in the window (or the override turned on or off) writes a new DynalispSysVarStamp (CDATE): a drawing already open applies the profile again when it becomes current and its SV:synced differs (Dyl:SetSync, while Settings sync is on).

The Window

  • c:Dyl-SysVars shows Res\Dyl-SysVars.xaml (Dyl:WinShow) and works on its locals: sv:sets (every profile, (name rows...)), sv:pst (the profile shown), sv:old (the names when it opened, to delete the files of the profiles deleted), sv:keep (the protected rows) and the selections sv:sel, sv:ksel, the texts typed in the boxes sv:box and the message sv:msg.
  • Every button but OK and Cancel closes the window with its number (2 a profile picked, 3 New..., 4 Copy..., 5 Rename..., 6 Delete, 7 Add, 8 Use current, 9 List..., 10 Remove, 11 Reset all; 12 to 15 the same buttons of the protected variables). sv:get keeps what the window got back (the rows selected, the boxes), the command does the work and shows it again on sv:vals. A row picked fills the boxes under its list in the window itself (dyl:Win.Fills), and the lists of several rows give the indexes selected ("0 3 5", sv:lines).
  • The name of a new, copied or renamed profile is asked in Res\Dyl-Name.xaml (sv:dlgname), shown again with the reason a name is refused (sv:nameerr: empty, not a valid file name, taken).
  • sv:state gives the mark of a row (*, (value not valid), (protected), (unknown)); sv:check refuses a read-only variable (Remote>>Dyl:SysVarWritable-p: its own value set back), a protected one in a profile, or a value of the wrong type.
  • Reset all (sv:reset) runs SysVarSetAll on the rows shown, at once.
  • The list window (sv:browse, Res\Dyl-SysVarsList.xaml, filtered in the window as Search is typed, the variable picked described under it with dyl:Win.Fills; Add 2 and AutoCAD Help 4 show it again, a double-click 3 closes it) reads sysvdlg.dat of the Express Tools (sv:catalog, from sv:catfile); AutoCAD Help (sv:brdoc) opens help.autodesk.com/view/ACD/<year>/<LOCALE>/?query=<variable> (System Variable), the year read from the AutoCAD folder.
  • OK runs sv:save: the user folder made, the files of the deleted profiles removed, each profile written with Remote>>LM:writecsv, the protected rows, the active profile and the stamp; then the profile is applied when the override is on.

Using It In An App

CallReturns
(Remote>>Dyl:SysVarProfile)The name of the active profile ("Default"), nil when there is none.
(Remote>>Dyl:SysVarRead "Default")The rows of a profile, (("PICKADD" "2") ...).
(Remote>>Dyl:SysVarApply)Applies the active profile, returns its status line.

Known Limitations

  • Nothing watches the variables: a value changed by hand stays until the next drawing opens, a profile is saved or Reset all.
  • A variable saved in the drawing is set for the session only, until the drawing is saved.
  • Without the Express Tools there is no sysvdlg.dat: the list window says so.
