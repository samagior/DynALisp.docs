Set Units

The developer docs of Set Units: its files and how its code works. What it does and how to use it are in its User Guide page.

Source FilesModules\Dynalisp\Remote\Dyl-DrawingSetup.lsp (the presets and the check of each drawing, loaded at startup), Modules\Dynalisp\Apps\Setup\Dyl-SetUnits.lsp (the commands)
DataThe unit system variables of the drawing; the user settings DynalispUnitsImperial, DynalispUnitsMetric (a preset key, "": not checked) and DynalispSetupOn
Shared withStandard Grid (the same Remote file), the Drawing Settings window of Dyl-Settings

The Presets

*ds:units* holds each preset as (key label ((variable . value) ...)). The values are system variables, so a drawing can be compared with a preset as well as set to it:

How It Works

Each command sets the unit system variables (LUNITS, LUPREC, AUNITS, AUPREC, ANGBASE, ANGDIR) and prints a confirmation:

CommandLengthLength precisionAngleAngle precision
UNITS-M0Decimal0Decimal degrees0
UNITS-M1Decimal0.0Decimal degrees0.0
UNITS-M2Decimal0.00Decimal degrees0.00
UNITS-I16Architectural1/16Decimal degrees0

All four set the base angle to East (0°) and angles counter-clockwise.

An architectural LUPREC of n is a precision of 1/2n inch (4: 1/16"). A new preset is a row of *ds:units* and a child command of Dyl-SetUnits.lsp.

The Commands

  • Each child, c:Pst-UnitsMetricMm … c:Pst-UnitsImperialSixteenthIn, is (su:apply key): (Remote>>Dyl:UnitsApply key) sets every variable of the preset, then the label is printed (Remote>>Dyl:UnitsName).
  • c:Dyl-SetUnits is Dyl:ChildPicker of dynalisp.mnl: a window listing the children of the file turned on in the Startup Suite, with their aliases, that runs the one double-clicked; *su:last* keeps the one picked last for the session.

Every Drawing

The Remote file loads at startup, so the check runs whether the commands are turned on or not:

  1. dynalisp.mnl runs Remote>>Dyl:SetupWatch as a startup step of each drawing (Dyl:StartupStep "Drawing settings"), when the Drawing Settings window of Dyl-Settings is saved, and when a drawing becomes current after a change made elsewhere (Settings sync).
  2. Nothing is done while DynalispSetupOn is off.
  3. Remote>>Dyl:SetupKind takes "Metric" or "Imperial" from MEASUREMENT; Remote>>Dyl:SetupDefault reads Dynalisp<Units|Grid><kind>, nil when it is empty or names a preset that no longer exists.
  4. Between acad-push-dbmod and acad-pop-dbmod (the drawing is not marked as modified, so a drawing only looked at is not asked to be saved), the units are set when Remote>>Dyl:Units-p finds a difference (each variable compared with equal and a fuzz of 1e-8), and the grid the same way.
  5. It returns a status line (metric drawing: units set to Metric 1 mm), kept by the startup for the command line and the diagnostics.

Using It In An App

CallDoes
(Remote>>Dyl:UnitsApply "MetricMm")Sets the units of a preset.
(Remote>>Dyl:Units-p "MetricMm")T when the drawing has them.
(Remote>>Dyl:SetupWatch)Checks the current drawing against the defaults, returns its status line.

Known Limitations

  • INSUNITS and MEASUREMENT are never set: the presets change how lengths and angles are shown, not what a unit is.
  • The units are set again each time the drawing opens until it is saved with them.
