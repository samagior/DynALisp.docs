Set File Preferences

The developer docs of Set File Preferences: its files and how its code works. What it does and how to use it are in its User Guide page.

Source FilesModules\Dynalisp\Remote\Dyl-FilePrefs.lsp (the preferences, the profile and its paths, loaded at startup), Modules\Dynalisp\Apps\Setup\Dyl-SetFilePrefs.lsp (the command), the File Preferences window of Dyl-Settings (Dyl:SetPrefsDlg in dynalisp.mnl)
DataModules\Dynalisp\Res\FilePrefs.csv (the paths), Res\Dictionaries (the custom dictionaries); the user settings DynalispPrefClass, DynalispPrefUnits, DynalispPrefLanguage, DynalispPrefProfile, DynalispPrefCustomDict, and the local ones DynalispPrefBase, DynalispPrefCustomBase, DynalispPrefApplied; the AutoCAD profiles and the AEC\<version> key of the registry

The Preferences

  • *fp:prefs* lists the three preferences, (what label ((key label) ...)): "Class", "Units", "Language"; the first choice is the default, the language of AutoCAD for the language. Remote>>Dyl:PrefGet and Remote>>Dyl:PrefSet read and write Dynalisp<Pref><what>.
  • *fp:langs* maps each language to its code (enu, fra...: the folder of its AutoCAD Architecture content and its Support\<code>.dct) and its lcid (the end of the product key).
  • *fp:version* is raised when the way a profile is set changes: every profile is then set again (Remote>>Dyl:PrefStamp is part of the stamp).

Setting The Profile, Step By Step

How It Works

  1. In Dyl-Settings, check File Preferences (Overrides), choose the preferences in its window (its open button) and Save. DYL-SETFILEPREFS asks for the same preferences on the command line (Enter keeps the current one) and turns the profile on.
  2. The first time, the DynALisp profile is made as a copy of the current profile, which is remembered as its base.
  3. The rows of Res\FilePrefs.csv that match the preferences give the paths. For each setting, the first matching row whose file or folder exists is used; the next rows are fallbacks. A setting with no matching row is left as it is.
  4. The registry options of AutoCAD Architecture are written while the profile is not current, then the profile is made current. AutoCAD keeps the current profile in memory and reads a profile again when it is made current. The options of the Files tab are then set in the current profile, the main dictionary of the language with them.
  5. Each drawing opened only checks the profile: a warning on the last line of the startup summary (--> ... run Dyl-SetFilePrefs ...) tells you to run DYL-SETFILEPREFS when the profile is not current, or when the preferences or FilePrefs.csv changed since it was set. A drawing never makes the profile current itself: a profile made current while a drawing opens reloads the menus of every open drawing and can stop AutoCAD. It does set the main and custom dictionaries of the preferences, in whichever profile is current, so a shortcut that starts AutoCAD with another profile (/p "AutoCAD Architecture (Global)") still gets the right spelling.
  6. Turned off in Dyl-Settings, the base profile is made current again. The DynALisp profile is kept.

In the code, (Remote>>Dyl:PrefApply T) (from Dyl-SetFilePrefs and the Save of Dyl-Settings):

  1. When the DynALisp profile is not current: it is copied from the current one when it does not exist (vla-CopyProfile), the current one is kept as its base (DynalispPrefBase), and the base is made current, so that the DynALisp profile can be written while it is not.
  2. Remote>>Dyl:PrefContent finds the AutoCAD Architecture content folder of the language, Remote>>Dyl:PrefContents the content of every installed language (the chosen one first).
  3. Remote>>Dyl:PrefTargets reads FilePrefs.csv (the user copy first) and keeps, per setting, the first row that matches the preferences (Remote>>Dyl:PrefMatch-p: the key, * or empty) and whose path exists, after Remote>>Dyl:PrefExpand (the tokens) and Remote>>Dyl:PrefResolve (the wildcards). It returns the targets and the settings not found.
  4. The Reg: rows are written under the key of the profile and the Aec: rows under AEC\<version> (Remote>>Dyl:PrefWrite); a Db: row gets the id of its database (Remote>>Dyl:PrefDbGuid: the id of a database already registered, else the one written inside the file, read with PowerShell, the database then added to the list) and becomes Current under Defaults\AecRcpBase80\Databases.
  5. The DynALisp profile is made current; then the Files: rows are put on (vla-get-Files (vla-get-Preferences acad)), the custom dictionary aside.
  6. Remote>>Dyl:PrefDictionarySet sets DCTMAIN to the dictionary of the language (enu when AutoCAD has none) and the custom dictionary of the language when it is on and DynALisp has one ({DYLU}: the user copy, made from its default), or, when a DynALisp one was current, the one it replaced (DynalispPrefCustomBase, else the sample.cus of AutoCAD).
  7. DynalispPrefApplied takes the stamp of the preferences and the file, and a status line is returned (paths set, dictionaries, what was not found).

Without T, as each drawing opens (a startup step of dynalisp.mnl), it only sets the dictionaries and returns a warning when the profile is not current or its stamp differs: making a profile current while a drawing opens reloads the menus of every drawing and can stop AutoCAD.

Paths File

Modules\Dynalisp\Res\FilePrefs.csv (a copy under User\ is used when there is one, see Dyl-UserFiles), one path per row: Setting;Classification;Units;Language;Value.

  • Setting:
    • Files:<property> sets an option of the Files tab, for example Files:TemplateDwgPath or Files:QNewTemplateFile.
    • Reg:<key>|<value>[,<value>...] sets profile values in the registry, for example Reg:Preferences\AecGuiBase80|SILocationRoot (the AEC style content folder).
    • Aec:<key>|<value>[,<value>...] sets an AutoCAD Architecture option shared by every profile of this AutoCAD (under AEC\<version>), for example Aec:General\Tools|ToolContentRoot (the tool catalog content root path). AutoCAD Architecture reads it when it starts, and it stays set when the profile is turned off.
    • Db:Components and Db:Keynotes set the current detail component and keynote databases. A database not yet registered in AutoCAD Architecture is added to its list under the id written inside the database file (read with PowerShell), since AutoCAD Architecture knows a database by that id.
  • Classification (CAWS, MasterFormat, OmniClass), Units (Metric, Imperial), Language (English, French, German, Chinese-Simplified...) give the preference the row is for. * or empty matches any.
  • Value is a path (several paths are separated by ;). {ACA} is the AutoCAD Architecture content folder of the language (C:\ProgramData\Autodesk\ACA 2027\enu, fra, deu..., found from the AEC content folder of the profile). {ACA*} tries the content folder of each installed language, the chosen one first, so a database missing from that content is found in the other language's. {DYL} is Modules\Dynalisp\Res. {DYLU} is its user copy under User\: the file is copied there from its default the first time, for a file AutoCAD writes to, such as a custom dictionary that gets the words you add while checking spelling. A file name can use * and ? (AecDtlComponents*.mdb): the first matching file of the folder is used.

The default rows set the DynALisp template folder and QNEW template, the French custom dictionary, and set the AEC content, style, IFC and project template folders and the tool catalog content root path by units and language. They also set the current detail component and keynote databases (Configure Detail Component / Keynote Databases), searched in the installed content and added to AutoCAD Architecture's list when missing:

  • NBS CAWS: Details (Global) for Metric (falling back to Details (UK)), Details (UK) for Imperial (falling back to Global). Both use the CAWS groups (D - Groundwork, E - In Situ Concrete...).
  • CSI MasterFormat: Details (FR) in French (falling back to Details (US)), Details (US) in English (falling back to Details (FR)), for both units.
  • Each one is taken from the content of the chosen language, else from the other installed language. The English 2027 content has no US or FR folder, so MasterFormat in English uses the US databases of the French content.

Using It In An App

CallReturns
(Remote>>Dyl:PrefGet "Units")"Metric", a key of the preference.
(Remote>>Dyl:PrefOn-p)T when the DynALisp profile is on.
(Remote>>Dyl:PrefApply T)Sets the profile now, returns its status line.

Known Limitations

  • The custom dictionary is set from the preferences: AutoCAD reads a changed dictionary only after a restart (see the Spell Dictionaries convention).
  • Acad (Imperial Ctb).dwt is not in Res\Templates\Model: Imperial falls back on Acad (Imperial Stb).dwt.
  • The English content of ACA 2027 has no Imperial or US folders, and the French one no Global folder: the fallback rows, or none, apply.
