Reopen Sheet Sets

The developer docs of Reopen Sheet Sets: its files and how its code works. What it does and how to use it are in its User Guide page.

Source FilesInstaller\Startup\SheetSets.cs and SheetSetMgr.cs, in the plugin of Clean Startup (DynALisp.Startup.csproj), built twice and committed: Contents\Resources\DynALisp.Startup.dll (.NET 8, AutoCAD 2025 and 2026) and Contents\Resources\Net10\DynALisp.Startup.dll (.NET 10, AutoCAD 2027 and later). The toggle: Dyl:SheetSetsOn-p and Dyl:SheetSetsSet in dynalisp.mnl
DataThe user settings DynalispSheetSetReopen ("1": on) and DynalispSheetSets (the files of the sheet sets remembered, divided by |; a setting of this computer, in *dyl:setslocal* and LocalSettings, never exported), read and written by the plugin itself in FixedProfile\General of the product key
FollowsThe Versions And Updates convention on plugins every version needs

How It Works

  1. The plugin reads DynalispSheetSetReopen itself when it loads, and again before each write: it never relies on a Lisp call made while DynALisp loads.
  2. What is open is read from the sheet set manager of AutoCAD, AcSmComponents.AcSmSheetSetMgr (one COM object for the session, the one of the palette), made by its ProgID (the unversioned one, then the one of the major version): GetDatabaseEnumerator, then GetFileName of each database. Its objects have no IDispatch (late binding fails: COM target does not implement IDispatch) and their interop assembly is versioned with AutoCAD, so SheetSetMgr.cs calls them through their virtual tables as the type library of the AutoCAD installed describes them: the library of the class (its TypeLib key, else an AcSmComponents*.tlb beside acad.exe), each interface found by its name and asked of the object, each method at the slot its FUNCDESC gives (oVft), its bases included. A name not found is an error, never a guess.
  3. The list is written when a command ends (or is cancelled or fails), when a drawing is made current or closed, and when AutoCAD quits (BeginQuit, then no more while it closes its drawings, again after QuitAborted), only when it changed: the order remembered first, then the sheet sets opened since. A sheet set closed in the manager is not open at the next of these moments, so it is dropped.
  4. At startup, nothing is written until the sheet sets are opened again: a timer (500 ms, on the dispatcher of AutoCAD) waits for a drawing and 2 seconds of quiet (Editor.IsQuiescent). A file that no longer exists is dropped and said on the command line. The others, when not open yet, are opened with _.OPENSHEETSET at the command line (FILEDIA 0, CMDECHO 0, both given back; SendStringToExecute of one Lisp expression, not echoed), which loads them into the palette.
  5. One second of quiet after the command, a sheet set still not open is opened in the manager itself (OpenDatabase, not failing when already open); one that still fails is kept in the list for the next startup and said on the command line. Then the list is written.
  6. Dyl:SheetSets is its Lisp function: (Dyl:SheetSets) says what it did at startup, (Dyl:SheetSets "Open") lists the sheet sets open in the manager now, (Dyl:SheetSets "Save") writes the list at once (Dyl:SheetSetsSet, when the setting is turned on; turned off, the list is emptied). The Settings window greys out the toggle when it is not defined.
  7. Dyl-Diagnostics (DynALisp section, dg:dyl-sheetsets): while the setting is on, what the plugin did, the sheet sets remembered (one whose file is missing is a problem) and those open in the manager; the plugin not loaded is a problem.

Limits

  • The Sheet Set Manager has no event for a sheet set closed in its palette: the list follows it at the next command, drawing made current or closed, or when AutoCAD quits. AutoCAD stopped on an error before that keeps the sheet set in the list.
  • A database opened by another program through the API, without the palette, is in the manager too: it is remembered and opened in the palette at the next startup.
