How It Works

  1. The plugin loads with AutoCAD, before the CUIx and its dynalisp.mnl. It holds one Store for the whole session (a static field): the files read, by full path (any case), each with the date of its last write (to the tenth of a microsecond) and its size.
  2. (Dyl:Data path n) gives the rows of the file, its header excluded, each cut or padded with "" to n cells: the same list as Remote>>Dyl:CsvRead made in Lisp (now Remote>>Dyl:CsvReadLisp, used when the plugin is not loaded), nil when the file does not exist or has no row. Each call looks at the date and the size of the file: when they did not change, the rows kept are given again; else the file is read again. A file that no longer exists is forgotten.
  3. A file is read as (open file "r") reads it, in the ANSI code page of Windows (GetACP), and divided as the Lisp side divides it (Csv.cs): the separator of its header (;, else a tab, else ,), each line divided step for step as Remote>>LM:csv->lst does, its odd cases too, each cell trimmed of its spaces, a blank line left out. (Dyl:DataHead path) gives the header as Remote>>Dyl:CsvHead, its UTF-8 byte order mark left out.
  4. Remote>>Dyl:CsvRead and Remote>>Dyl:CsvHead call Dyl:Data and Dyl:DataHead when they are defined, so every reader (the layer keys, the presets and their engine, the materials, the groups, the simulation...) uses the plugin with no change of its own. The caches of the Lisp side (*pst:readcache*, *lk:readcache*) stay: they keep the rows once cleaned, for one drawing; the plugin makes their first read in each drawing a copy of rows already divided, the 387 KB of QuickDrawAssemblies.csv no longer divided again in Lisp in each drawing.
  5. Every writer of these files calls Remote>>Dyl:CsvWrite (Remote>>LM:writecsv, then (Dyl:DataDrop path)): the clock of Windows moves by steps of about 15 ms, so a file written twice in one step at the same size would keep its date. A file changed out of DynALisp (Excel, another drawing, git pull) gets another date and is read again.
  6. The startup of each drawing (dynalisp.mnl) reads the index of the Startup Suite and the aliases with Dyl:SuiteCsv: the header and the rows given by Dyl:DataHead and Dyl:Data, else divided in Lisp as before. Dyl:SuiteRecsOf and Dyl:AliasRead read through it; Dyl:SuiteReadFile, at each startup, takes only the 4 columns it reads of the 9 of the index ((Dyl:DataCols path i ...)), the names and descriptions, most of its 150 KB, left in .NET. Its time is shown in three steps (Startup Suite: Apps files listed, index read, index checked); Dyl:SuiteWrite and Dyl:AliasWrite tell the plugin the file was written (Dyl:SuiteCsvDone). PrepSuite.csv keeps its own reader: a column missing from a row of its user copy (a command added since) takes the default step, which a row padded with "" would turn off.
  7. Each list given to the Lisp is made at once from an array of values (new ResultBuffer(TypedValue[])), never with an Add for each value: the 735 rows of the index given that way took longer than dividing the file in Lisp (281 ms against 155 ms).
  8. (Dyl:DataInfo) gives (("Files" . n) ("Reads" . n) ("Hits" . n) ("ReadMs" . ms)): the files kept, the reads of a file, the calls given a file kept and the time spent reading, shown by Dyl-Diagnostics.

The Presets, Groups And Aliases

The library holds the data part of the preset engine, the step before the Manager moves to .NET (nothing calls it yet). Each function gives what the Lisp function it is named after gives from the same files:

C#LispWhat it gives
Presets.File, Presets.CsvRemote>>Dyl:PresetFile, Remote>>Dyl:PresetCsvThe file of a tool (its user copy, else its default; the default for a user copy whose header begins otherwise, head) and its rows, as many cells as the header
Presets.Clean, Presets.Ids, Presets.CamelRemote>>Dyl:PresetClean, Remote>>Dyl:PresetIds, Remote>>Dyl:PresetCamelThe rows cleaned (an id neither default nor custom cleared, a default given again and a row without name dropped), the presets without id given one from their name (cu-Name, unique in any case)
Presets.Read, Presets.DefsOfRemote>>Dyl:PresetRead, Remote>>Dyl:MaterialDefsOfThe presets with the defaults missing from the file, kept while none of the files of the presets and the groups changed; the defaults from the default file
Presets.Write, Presets.CommandRemote>>Dyl:PresetWrite, Remote>>Dyl:PresetCommandThe presets written to the user copy (Csv.WriteFile: the file of Remote>>LM:writecsv, byte for byte), the command of a preset
Groups.Of, Groups.CaseOf, Groups.WriteRemote>>Dyl:GroupsOf, Remote>>Dyl:GroupCaseOf, Remote>>Dyl:GroupsWriteOfThe groups of the presets or of the materials, a group as they write it, the groups written
Aliases.Read, Aliases.Of, Aliases.WriteDyl:AliasRead, Dyl:AliasesOf, Dyl:AliasWriteThe aliases of Aliases.csv, those of a command, the aliases written sorted

The folders come from a Bundle (Bundle.cs): its Contents and User folders, the user copy of a file (Dyl:UserFile, Dyl:UserFileW), the list separator of Windows and the code page the files are written in. The specs of the tools (Presets.All) are those of *dyl:presetspecs*: a test reads them in the Lisp files and compares. What a tool does to each of its rows (its fix) and its defaults come with its tab.

Witness Files

The C# is checked against what the Lisp gives in AutoCAD, not against what it is thought to give. Installer\Core\Tests\Witness\Witness.lsp, loaded in AutoCAD with DynALisp started ((load (strcat *dyl:repo "\\Installer\\Core\\Tests\\Witness\\Witness.lsp"))), runs the Lisp on each case of Witness\In: a copy of its folder in %TEMP% (a Contents and a User folder of its own), the Lisp pointed at it for a moment (*dyl:contents, *dyl:user, *dyl:dylres, *dyl:res, *dyl:alias) and Dyl:Data hidden, so the Lisp reads the files itself. It writes, for each tool, its file, header, rows, defaults, rows cleaned, presets and commands, then the groups and the aliases, and the files it writes; Probes.txt holds strcase, <, acad_strlsort and the CamelCase on the names of In\Probes.csv. Its zip, put in Witness\Lisp, is compared by WitnessTests.cs: the C# does the same steps on the same cases, every section must give the same lines and every file written the same bytes. The cases: defaults (the default files of DynALisp, copied), edges (ids, names, separators, quotes, an older header, groups, aliases) and empty (no file). .gitattributes keeps the bytes of Witness as they are.

Diagnostics

The DynALisp section of Dyl-Diagnostics shows the Data files line (Dyl:DataInfo), and a [!] line when Dyl:Data is not defined (the DLL is not loaded): each drawing then reads the files again in Lisp.
