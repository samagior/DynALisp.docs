Core

The developer docs of Core: its files and how its code works. What it does is in its User Guide page.

How It Works

  1. The plugin loads with AutoCAD, before the CUIx and its dynalisp.mnl. It holds one Store for the whole session (a static field): the files read, by full path (any case), each with the date of its last write (to the tenth of a microsecond) and its size.
  2. (Dyl:Data path n) gives the rows of the file, its header excluded, each cut or padded with "" to n cells: the same list as Remote>>Dyl:CsvRead made in Lisp (now Remote>>Dyl:CsvReadLisp, used when the plugin is not loaded), nil when the file does not exist or has no row. Each call looks at the date and the size of the file: when they did not change, the rows kept are given again; else the file is read again. A file that no longer exists is forgotten.
  3. A file is read as (open file "r") reads it, in the ANSI code page of Windows (GetACP), and divided as the Lisp side divides it (Csv.cs): the separator of its header (;, else a tab, else ,), each line divided step for step as Remote>>LM:csv->lst does, its odd cases too, each cell trimmed of its spaces, a blank line left out. (Dyl:DataHead path) gives the header as Remote>>Dyl:CsvHead, its UTF-8 byte order mark left out.
  4. Remote>>Dyl:CsvRead and Remote>>Dyl:CsvHead call Dyl:Data and Dyl:DataHead when they are defined, so every reader (the layer keys, the presets and their engine, the materials, the groups, the simulation...) uses the plugin with no change of its own. The caches of the Lisp side (*pst:readcache*, *lk:readcache*) stay: they keep the rows once cleaned, for one drawing; the plugin makes their first read in each drawing a copy of rows already divided, the 387 KB of QuickDrawAssemblies.csv no longer divided again in Lisp in each drawing.
  5. Every writer of these files calls Remote>>Dyl:CsvWrite (Remote>>LM:writecsv, then (Dyl:DataDrop path)): the clock of Windows moves by steps of about 15 ms, so a file written twice in one step at the same size would keep its date. A file changed out of DynALisp (Excel, another drawing, git pull) gets another date and is read again.
  6. The startup of each drawing (dynalisp.mnl) reads the index of the Startup Suite and the aliases with Dyl:SuiteCsv: the header and the rows given by Dyl:DataHead and Dyl:Data, else divided in Lisp as before. Dyl:SuiteRecsOf and Dyl:AliasRead read through it; Dyl:SuiteReadFile, at each startup, takes only the 4 columns it reads of the 9 of the index ((Dyl:DataCols path i ...)), the names and descriptions, most of its 150 KB, left in .NET. Its time is shown in three steps (Startup Suite: Apps files listed, index read, index checked); Dyl:SuiteWrite and Dyl:AliasWrite tell the plugin the file was written (Dyl:SuiteCsvDone). PrepSuite.csv keeps its own reader: a column missing from a row of its user copy (a command added since) takes the default step, which a row padded with "" would turn off.
  7. Each list given to the Lisp is made at once from an array of values (new ResultBuffer(TypedValue[])), never with an Add for each value: the 735 rows of the index given that way took longer than dividing the file in Lisp (281 ms against 155 ms).
  8. (Dyl:DataInfo) gives (("Files" . n) ("Reads" . n) ("Hits" . n) ("ReadMs" . ms)): the files kept, the reads of a file, the calls given a file kept and the time spent reading, shown by Dyl-Diagnostics.

The Presets, Groups And Aliases

The library holds the data part of the preset engine, the step before the Manager moves to .NET (the assemblies read by the plugin use it, see below). Each function gives what the Lisp function it is named after gives from the same files:

C#LispWhat it gives
Presets.File, Presets.CsvRemote>>Dyl:PresetFile, Remote>>Dyl:PresetCsvThe file of a tool (its user copy, else its default; the default for a user copy whose header begins otherwise, head) and its rows, as many cells as the header
Presets.Clean, Presets.Ids, Presets.CamelRemote>>Dyl:PresetClean, Remote>>Dyl:PresetIds, Remote>>Dyl:PresetCamelThe rows cleaned (an id neither default nor custom cleared, a default given again and a row without name dropped), the presets without id given one from their name (cu-Name, unique in any case)
Presets.Read, Presets.DefsOfRemote>>Dyl:PresetRead, Remote>>Dyl:MaterialDefsOfThe presets with the defaults missing from the file, kept while none of the files of the presets and the groups changed; the defaults from the default file
Presets.Write, Presets.CommandRemote>>Dyl:PresetWrite, Remote>>Dyl:PresetCommandThe presets written to the user copy (Csv.WriteFile: the file of Remote>>LM:writecsv, byte for byte), the command of a preset
Groups.Of, Groups.CaseOf, Groups.WriteRemote>>Dyl:GroupsOf, Remote>>Dyl:GroupCaseOf, Remote>>Dyl:GroupsWriteOfThe groups of the presets or of the materials, a group as they write it, the groups written
Aliases.Read, Aliases.Of, Aliases.WriteDyl:AliasRead, Dyl:AliasesOf, Dyl:AliasWriteThe aliases of Aliases.csv, those of a command, the aliases written sorted

The folders come from a Bundle (Bundle.cs): its Contents and User folders, the user copy of a file (Dyl:UserFile, Dyl:UserFileW), the list separator of Windows and the code page the files are written in. The specs of the tools (Presets.All) are those of *dyl:presetspecs*: a test reads them in the Lisp files and compares. What a tool does to each of its rows (its fix) and its defaults come with its tab.

The Assemblies

The assemblies of Quick Draw (Res\QuickDrawAssemblies.csv) are read, fixed and put in the units of the drawing by the plugin (Data\Assemblies.cs): read and fixed in Lisp, the 860 assemblies took 0.9 s of the first window of each session.

C#LispWhat it gives
Assemblies.Layers, Assemblies.LayersStrRemote>>Dyl:MaterialLayers, Remote>>Dyl:MaterialLayersStrThe layers of a text (the valid ones, their band settings, border, hatch and framing), and the text of layers
Assemblies.Lines, Assemblies.LinesStrRemote>>Dyl:MaterialLines, Remote>>Dyl:MaterialLinesStrThe Border lines or Dividing lines of a text, and their text
Assemblies.Fix, Assemblies.DefsDyl:QuickDrawAsmFix, Dyl:QuickDrawAsmDefsA row fixed (its family, exterior, units, group, the lines and spaces of an older file), the default assemblies
Assemblies.Scale, Assemblies.ReadDyl:QuickDrawAsmScale, Dyl:QuickDrawAsmReadAllThe thicknesses of an assembly in millimetres in the units of the drawing; the assemblies read, fixed and scaled, kept while none of the files changed
Lisp.Distof, Lisp.Rtos, Lisp.NumPdistof, rtos, Remote>>Dyl:MaterialNumPA text read as a number, a number written with its decimals and the zeros of DIMZIN

(Dyl:AsmDefs contents) and (Dyl:AsmRead contents factor dimzin) give them to Dyl:QuickDrawAsmDefs and Dyl:QuickDrawAsmReadAll, which read them in Lisp when the plugin is not loaded. contents is *dyl:contents (a Bundle for each), factor the drawing units in a millimetre (Dyl:QuickDrawAsmFactor) and dimzin the DIMZIN of the drawing, which rtos follows. A layer of an older file whose material is the id of a Quick Draw preset takes the material of that preset (Dyl:QuickDrawAsmFixLayer): the plugin does not read the presets of Quick Draw, so for such a file Dyl:AsmRead gives nil and the Lisp reads it.

The Materials

The hatch presets (Res\HatchPresets.csv) and the materials (Res\Materials.csv) are read and fixed by the plugin too (Data\Materials.cs): every tool that draws, the Manager, the Assistant and the simulation read them through Remote>>Dyl:MaterialBoth, and the windows read their defaults to show a row as default or modified.

C#LispWhat it gives
Materials.Fix, Materials.HatchDefsRemote>>Dyl:MaterialFix, Remote>>Dyl:HatchPresetDefsA hatch preset fixed (its 64 columns, its type, its bands and behaviors, the values in capitals, the on/off columns, a row set for another drawing scale set for 1:1), the default hatch presets
Materials.RowFix, Materials.RowDefsRemote>>Dyl:MaterialRowFix, Remote>>Dyl:MaterialRowDefsA material fixed (its group, its data numbers greater than 0, a decimal comma read as a point), the default materials
Materials.OldP, Materials.BothRemote>>Dyl:MaterialOld-p, Remote>>Dyl:MaterialBothWhether the materials file is one of DynALisp 1.1; the hatch presets and the materials read, fixed and cleaned, the defaults missing added, kept while none of the files changed

(Dyl:HatchDefs contents dimzin), (Dyl:MatDefs contents) and (Dyl:MatBoth contents dimzin) give them to the three Lisp functions, which read the files themselves when the plugin is not loaded or gives nil. It gives nil for what only the Lisp has: the defaults written in its code (*hp:defaults*, *mt:defaults*) when a default file is missing, a materials file of DynALisp 1.1, split into materials and hatch presets by Remote>>Dyl:MaterialMigrate (which writes both files). A material of an older file in the group Section or Elevation gets the group of its default in *mt:defaults*, as in the Lisp: Materials.CodeGroups holds the id and group of each material of that list, checked against the Lisp by the tests (left to the Lisp, such a file of a user made every window of the assemblies fall back to the Lisp). dimzin is there for the scale of a row set for another drawing scale, written with rtos. Joining a material to its hatch preset (Remote>>Dyl:MaterialJoinAs) stays in Lisp: it takes no time.

What the Windows Show

What the Quick Draw window shows of each assembly (its layers, its width, its preview with its lines, its description with its thermal resistance, its mass and its ratings) is made by the plugin too (Data\Shows.cs): made in Lisp, the 860 assemblies took 1.2 s of the first window of each session.

C#LispWhat it gives
Shows.AllDyl:QuickDrawAsmShows, Dyl:QuickDrawAsmShowWhat is shown of each assembly read, kept while none of the files, the units of the drawing nor the patterns changed
Shows.Desc, Shows.RatingsDyl:QuickDrawLayersDesc, Dyl:QuickDrawAsmRatingsTextThe description of the layers, the ratings
Shows.Data, Shows.DataText, Shows.SigRemote>>Dyl:MaterialAssemblyData, Remote>>Dyl:MaterialAssemblyText, Remote>>Dyl:MaterialSigThe thermal resistance, mass, continuous layers and low permeance ratio of an assembly, as text
Shows.Preview, Shows.BandDyl:QuickDrawGalleryLayers, Remote>>Dyl:MaterialBandThe preview of an assembly, a band of it
Shows.PatternsRemote>>Dyl:MaterialPatUnitsThe patterns previewed, whose units the Lisp gives

(Dyl:AsmPats contents cannoscale measurement insunits lunits luprec dimzin) gives the patterns of the layers previewed; the Lisp finds the units of each one (Remote>>Dyl:MaterialPatUnits: a .pat file on the support path of AutoCAD) and gives them to (Dyl:AsmShows contents cannoscale ... dimzin pattern units file ...), which gives the rows in the order the assemblies were read; Dyl:QuickDrawAsmShowsCore puts them in the order of the list (the places kept in *qd:asmsorted*) and checks each id. The system variables are those of the drawing (CANNOSCALEVALUE, MEASUREMENT, INSUNITS, LUNITS, LUPREC, DIMZIN); lengths that are not decimal (LUNITS other than 2: rtos then writes feet and inches or fractions) are left to the Lisp, as the assemblies and materials it reads itself.

What the Assembly Presets Window Is Given

What the Assembly Presets window is given of the assemblies and the materials is made by the plugin too (Data\AsmWindow.cs): made in Lisp, the materials of the layers of the 860 assemblies and the rows of their layers (860 assemblies and 860 defaults) were made again in each drawing the tab opened in.

C#LispWhat it gives
AsmWindow.MatsDyl:QuickDrawAsmWinMatsThe materials of the Material list of a layer (by group, then by name; those that no longer exist last, marked), the groups of the Group list, the layer keys the assemblies use
AsmWindow.Defqa:def of Dyl:QuickDrawAsmWinPrepThe row Add starts from
AsmWindow.Extra, AsmWindow.RowsDyl:QuickDrawAsmExtra, Dyl:QuickDrawLayersRowsThe columns the window adds to an assembly: its layers as rows in the units of the drawing, its Border lines and its Dividing lines
AsmWindow.DataRemote>>Dyl:MaterialDataListsThe thermal resistance and the mass of each material, per unit of thickness

(Dyl:AsmWinMats contents dimzin ((layers border dividing) ...)) gives (mats groups keys) for the assemblies of the window, each material with the index of its row among those of Dyl:MatBoth, so Dyl:QuickDrawAsmWinMatsCore joins it to the row the Lisp already has (Remote>>Dyl:MaterialRead); the layer keys stay in the Lisp (Remote>>Dyl:MaterialDlgKeys makes mt:keys from those used), and so do the key of new lines and the row Add starts from, given to (Dyl:AsmRows contents measurement insunits dimzin bk def ((layers border dividing units) ...)), which gives the columns of every assembly at once (wrows of the dialog, see Remote>>Dyl:PresetWinRowsOf). (Dyl:MatData contents measurement insunits dimzin (id ...)) gives the data of the materials (Remote>>Dyl:MaterialDataLists without its rows). Each gives nil when the Lisp reads the materials itself (a materials file of DynALisp 1.1), and the Lisp then makes them.

Witness Files

The C# is checked against what the Lisp gives in AutoCAD, not against what it is thought to give. Installer\Core\Tests\Witness\Witness.lsp, loaded in AutoCAD with DynALisp started (Pst-DiagnosticsWitness, DIAG-WITNESS), runs the Lisp on each case of Witness\In: a copy of its folder in %TEMP% (a Contents and a User folder of its own), the Lisp pointed at it for a moment (*dyl:contents, *dyl:user, *dyl:dylres, *dyl:res, *dyl:alias) and Dyl:Data hidden, so the Lisp reads the files itself. It writes, for each tool, its file, header, rows, defaults, rows cleaned, presets and commands, then the groups, the aliases, the assemblies (the defaults, read and fixed, in inches and metres with DIMZIN 0 and 8, and back) the hatch presets and materials (whether the file is one of DynALisp 1.1, the defaults and both read, with DIMZIN 0 and 4) what the Quick Draw window shows of each assembly (in a metric drawing and in an imperial one, at 1:50, the units of the patterns those of a rule of the witness, wt:pat, never the .pat files of the computer, the newlines of a description written as the character 29) and what the Assembly Presets window is given (in the same drawings: its materials, groups and layer keys used, the data of the materials, the key of new lines and the row Add starts from, the layer keys those of the case, and the columns it adds to each assembly), and the files it writes; Probes.txt holds strcase, <, acad_strlsort and the CamelCase on the names of In\Probes.csv, distof on texts and rtos on numbers with each DIMZIN. Its zip, put in Witness\Lisp, is compared by WitnessTests.cs: the C# does the same steps on the same cases, every section must give the same lines and every file written the same bytes. The cases: defaults (the default files of DynALisp, copied), edges (ids, names, separators, quotes, an older header, groups, aliases) empty (no file), assemblies (older rows: lines and spaces as layers, no family; layers of every kind, odd numbers), assemblies-preset (a layer made of a Quick Draw preset, read by the Lisp: the C# gives nil, and only the defaults are compared), materials (every fix of a hatch preset and of a material, user rows, groups in any case) and materials-section (materials in the group Section, given their default group) and shows (assemblies of every kind of layer, line, pattern and rating, in inches and millimetres). The materials of a case without the default files (empty, assemblies) are read by the Lisp too: only whether the file is old is compared, and of what is shown (edges too, its materials file of DynALisp 1.1) only the drawing scale, and nothing of what the Assembly Presets window is given. .gitattributes keeps the bytes of Witness as they are.

The first witness (AutoCAD Architecture 2027, list separator ;, code page 1252) confirmed every line and every file of the C#: write-line ends a line with a carriage return and a line feed, the files are written in the ANSI code page, strcase makes the accented letters capitals (ß stays), < compares the codes of the characters. Only acad_strlsort sorts otherwise, by the order of the words of Windows (no case, no accent, lower case first on a tie): Aliases.Order follows it for the names of commands, the only names it sorts here (-, then _, the digits, the letters).

The witness of the assemblies (same AutoCAD) confirmed every row read, fixed and scaled, and showed how distof and rtos work: distof takes spaces around the number, an exponent without digits (5e) and fractions (1/2, 1 1/2); rtos reads the number to 16 significant digits, then rounds half away from zero (2.675 to 2.68, 0.5 to 1), keeps no more decimals than 16 digits hold (1000.000000000000) and never writes -0. Lisp.Distof and Lisp.Rtos do the same.

The witness of the materials (same AutoCAD) confirmed every hatch preset and material read and fixed, with each DIMZIN. A fix gives a new row, never changes the row it is given: the rows of a file are shared by every read of the session (a fix that changed them in place wrote the user copy of the materials with the values fixed).

Diagnostics

The DynALisp section of Dyl-Diagnostics shows the Data files line (Dyl:DataInfo), and a [!] line when Dyl:Data is not defined (the DLL is not loaded): each drawing then reads the files again in Lisp.
