Fix Blocks ByBlock

The developer docs of Fix Blocks ByBlock: its files and how its code works. What it does and how to use it are in its User Guide page.

Source FilesModules\Dynalisp\Apps\Cleaning\Dyl-SetByBlock.lsp
DataNone: the block definitions of the drawing are changed in place.

The Commands

One Apps file, autoloaded: c:Dyl-SetByBlock (alias FIXBLKS) and its child c:Pst-SelectAllBlocks (alias SL-BLOCKALL).

FIXBLKS, step by step

  1. (ssget '((0 . "INSERT"))) takes the block references selected.
  2. The work is one undo group: (vl-cmdf "_.undo" "_BEgin") … "_End".
  3. For each reference, the local function FIX1 gets the name of its block (code 2) and fixes the definition:
    • A definition already fixed is skipped: its name is kept in FLST.
    • (tblobjname "block" name) gives the block record, and entnext walks every entity of the definition.
    • A nested INSERT is followed: FIX1 runs on its own definition.
    • Any other entity gets, through ActiveX and each in a vl-catch-all-apply (an entity that refuses one is left as it is): layer "0", color 0 (ByBlock), linetype "Byblock", lineweight -2 (ByBlock).
  4. _.regen shows the change on every reference.

SL-BLOCKALL

(ssget "_X" '((0 . "INSERT"))) takes every block reference of the drawing (every space, xrefs included), and _.PSELECT makes it the current selection, with grips, for the next command.

Known Limitations

  • FLST is cleared for each reference selected, so a definition shared by several selected references is fixed again for each one (the result is the same, only slower).
  • An empty selection passes nil to sslength, which stops the command with an error after the undo group has begun.
  • The plot style is not set (vla-put-PlotStyleName is commented out in the source).
  • Attribute references (ATTRIB) belong to the references, not to the definitions, so they keep their properties.
