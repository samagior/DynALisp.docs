Data Links

The developer docs of Data Links: its files and how its code works. What it does and how to use it are in its User Guide page.

Source FilesModules\Dynalisp\Apps\Cleaning\Dyl-DataLinks.lsp (the functions, the window, the commands)
DataThe ACAD_DATALINK dictionary of the drawing and the tables (ACAD_TABLE, TABLECONTENT) that use its links
UsesMAJ:cmd-silent of dynalisp.mnl, Remote>>LM:lst->str

The Link Record

Every function works on one list per link, made by Dyl:DataLinkInfo:

(name ename status tables file connection)

status is "OK", "Missing file" or "No source"; tables the enames of the tables that use the link (nil: unused); connection the full string, "C:\...\Book.xlsx!Sheet1!A1:D9".

Finding The Links And Their Tables

  1. Dyl:DataLinkList reads the ACAD_DATALINK dictionary of (namedobjdict): each name (code 3) followed by its object (code 350 or 360), sorted by name.
  2. A link is used when either side says so, so that a link is never reported unused by mistake:
    • Dyl:DataLinkPtrs: every table of the drawing ((ssget "_X" '((0 . "ACAD_TABLE")))) is read; an ename of a link found in its data, or in the data of its TABLECONTENT objects (codes 340 and 360), counts.
    • Dyl:DataLinkUsers: the users the link lists itself (its code 330), when they still exist (an erased table gives no data); a table content counts as its table, or as itself when its owner is not a table.
    Dyl:DataLinkAdd merges both into one association list, each table once.
  3. Dyl:DataLinkFile takes the file from the connection string (code 302), up to the first !; Dyl:DataLinkFound looks for it with findfile, and a relative path (.\Book.xlsx) from DWGPREFIX.

Deleting

  • Dyl:DataLinkDelete deletes the object through ActiveX (vla-delete); when that fails, it removes the entry from the dictionary (dictremove) and deletes the object (entdel). It returns T when the link is gone.
  • Dyl:DataLinkDeleteAll deletes a list of records inside one undo mark (vla-StartUndoMark / vla-EndUndoMark), so one U restores them, and returns the count.
  • A table is never touched: it only loses its link.

The Data Links Window

  • c:Dyl-DataLinks stops at once when the drawing has no link. It writes the window to a temporary DCL file (Dyl:DataLinkDcl) and runs Dyl:DataLinkDlgRun in a vl-catch-all-apply: an error closes the window (term_dialog) and is printed, never left open.
  • Its locals: dl:lst (the records), dl:sel (the names selected), dl:upd (the tables to update). Dyl:DataLinkDlgShow fills the list, Dyl:DataLinkDlgDetails the lines under it (Dyl:DataLinkWhere gives the layouts of the tables, code 410, or a block definition).
  • Select unused and Select missing file run Dyl:DataLinkDlgSelect with a test on the records; Delete selected (Dyl:DataLinkDlgDelete) asks first, says how many are used by tables, deletes, reads the records again.
  • The window closes with a code: 0 Close; 2 Data Link Manager..., which then sends _.DATALINK with vla-SendCommand; 3 Update tables: Dyl:DataLinkDlgUpdate keeps the tables of the selected links that are in a layout (code 410: the ones a selection set can hold), the command runs (MAJ:cmd-silent (list "_.DATALINKUPDATE" "_U" ss "")), which never leaves the command waiting for input, and the loop opens the window again.

DLPURGE

c:Pst-DataLinkPurge reads the records, prints the names of the unused ones, asks with getkword ([Yes/No] <Yes>), deletes them with Dyl:DataLinkDeleteAll, then prints the used links whose status is Missing file.

Using It In An App

CallReturns
(Dyl:DataLinkInfo)The records of every link of the drawing (defined once a command of the file has run).
(Dyl:DataLinkDeleteAll records)Deletes them in one undo mark, returns how many.

These are functions of an Apps file: an App checks Dyl:SuiteFileOn-p and loads it (Dyl:SuiteFileLoad) before calling them, as the Folders convention says.

Known Limitations

  • The tables are found with ssget "_X", which does not reach the block definitions: a link used only there counts only when it lists the table itself.
  • The window is written from Lisp strings to a temporary file; the Folders convention keeps the dialogs in Res.
