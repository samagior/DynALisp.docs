Materials

The developer docs of Materials: its files and how its code works. What it does and how to use it are in its User Guide page.

DataRes\Materials.csv and Res\HatchPresets.csv (your copies under User)

Materials File

The materials are saved in Res\Materials.csv (semicolons, one material per row, with a header; the spec Material). Your changes go to its copy under User; the shipped file under Contents gives the default values (status, Reset Selected, Reset All). The columns, in order: Id, Group, Name; Cut, the id of its hatch preset in section ("": no hatch), and Surface, its hatch preset in elevation ("": the same as Cut; not used yet); then its data, in SI units, "" when not known: Conductivity (W/m·K), Density (kg/m³) and Resistance, a fixed RSI (m²·K/W) for what its thickness does not give (an air space, a membrane). Each row is cleaned by Remote>>Dyl:MaterialRowFix (its group as in the groups, a value of its data a number greater than 0, a decimal comma read as a point). An id starting with mt- is a default material, cu- a custom one.

The Material Joined To Its Hatch Preset

A tool never reads the two files itself: Remote>>Dyl:MaterialGet (one id) and Remote>>Dyl:MaterialRead (every material) return each material joined to its hatch preset (Remote>>Dyl:MaterialJoin): the id, group and name of the material, then the columns of its Cut hatch preset (Remote>>Dyl:MaterialHatchPreset), the row of 64 columns the tools drew with when a material held its hatch, so Quick Draw, Quick Shape, the previews and the assemblies read it as before. A material without a hatch preset, or whose hatch preset no longer exists, is joined to *hp:none*: no pattern, no hatch. Remote>>Dyl:MaterialDefs joins the shipped materials to the shipped hatch presets (Remote>>Dyl:MaterialRowDefs, Remote>>Dyl:HatchPresetDefs, each read again when its file changes). Both files are read by Remote>>Dyl:MaterialBoth: (hatch-presets materials).

Files Of DynALisp 1.1 And Older

Up to DynALisp 1.1, Materials.csv held a hatch in each row (the columns of HatchPresets.csv today). Remote>>Dyl:MaterialOld-p tells a user copy of that kind by its header (Pattern in column 3; the answer kept until the file changes, *mt:oldstamp*), and Remote>>Dyl:MaterialMigrate, called by every reader before it reads, splits it: each material is given, in the order of the file,

  1. the hatch preset already given the same hatch in this split (every column after the name equal), or a custom one of that hatch (made by a split whose materials could not be written);
  2. else the hatch preset of its default material (mt-Brick: hp-Brick), not given a hatch yet in this split, which gets the hatch of the file (the user's changes kept);
  3. else a new custom hatch preset named after the material (Remote>>Dyl:PresetIds: cu-Hardboard when hp-Brick was given another hatch).

The material keeps its id, group and name, with no data. The hatch presets are written first, then the materials; when one cannot be written (open in Excel), nothing more is written, the split is used from memory and made again at the next read (told once a session). Until then the spec (head . 4) keeps the old copy from being read as the new format (Remote>>Dyl:PresetFile), and the writers of every preset file split it first (Remote>>Dyl:GroupsRename, Remote>>Dyl:HatchPresetDialog). Dyl-Diagnostics reports a file not split yet (it never splits it), the materials whose hatch preset no longer exists, and a User copy of the HatchPresets.csv of DynALisp 1.0.

The Code

  • The window – Remote>>Dyl:MaterialDialog opens the Hatch Presets window on the hatch preset of the material, and returns the material on OK (the open button beside Material of the Quick Draw and Quick Shape windows).
  • The hatch, its scale and its previews – see Hatch Presets: they are read from the material joined to its hatch preset.
