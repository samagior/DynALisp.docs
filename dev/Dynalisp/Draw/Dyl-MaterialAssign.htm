Assign Material

The developer docs of the material written on the objects of a drawing, and of the Assign Material window. What it does and how to use it are in its User Guide page.

Source FilesModules\Dynalisp\Remote\Dyl-Materials.lsp (the data written on the objects, the hatch that writes them, loaded at startup), Modules\Dynalisp\Apps\Draw\Dyl-Materials.lsp (the commands Pst-MaterialAssign, Pst-MaterialMatch, Pst-MaterialShow), Apps\Draw\Dyl-QuickDraw.lsp and Apps\Draw\Dyl-QuickShape.lsp (what they add: the tool, the preset, the layer of an assembly)
DataThe extended data of the application DYNALISP on each hatch or closed outline; the window Res\Dyl-MaterialAssign.xaml; the layer key MATREGION (Res\LayerKeys.csv)
FollowsThe Presets And Materials convention: an object carries the id of its material, never its values

The Data On An Object

An object made of a material carries the extended data (XData) of the application DYNALISP (*mt:app*): strings "Key=value" (group 1000), any number of them, so another tool can add keys of its own without a format of its own. They follow the object through COPY, MOVE, MIRROR, an associative hatch stretched with its boundary, and are read in Lisp with (entget e '("DYNALISP")) or in .NET with Entity.GetXDataForApplication("DYNALISP"). The keys:

KeyValue
FormatThe version of these data, 1 (*mt:tagformat*), always first.
MaterialThe id of the material (mt-Brick, cu-...), never its values: the values are read from the materials file when they are needed, so a material changed in the Materials window changes every object made of it.
Tool, PresetThe tool that drew it (QuickDraw, QuickShape) and the id of its preset. Dropped when the material is given by hand.
Assembly, LayerFor a layer of an assembly: the id of the assembly preset and the number of the layer in it, 1 the first, whichever way the band was drawn (Flip, justification), so a simulation can read the layer (its framing, its load-bearing) from the assembly preset.
RoleLegend: a box of a legend (mt:legend of Remote>>Dyl:MaterialLegend), a sample, not a part of a detail.

Only a hatch or a closed curve carries a material (Remote>>Dyl:MaterialTaggable-p, the types of *mt:tagtypes*): the region of a hatch is inside its boundary loops, an island outside; that of a closed curve inside the curve.

The Code

  • Read – Remote>>Dyl:MaterialTags returns the data of an entity, (("Key" . "value") ...); Remote>>Dyl:MaterialTag one key (any case); Remote>>Dyl:MaterialOf the id of its material, nil when it has none.
  • Write – Remote>>Dyl:MaterialTagPut puts keys in the data of an entity, the others kept, a key given nil or "" removed, the data removed once no key is left (the application registered first). It writes with vla-SetXData, never entmod, which would rewrite a hatch whole; it returns nil when the object cannot be changed (a locked layer).
  • The hatch – Remote>>Dyl:MaterialHatchAt (and so Remote>>Dyl:MaterialHatch, the one path of every hatch of Quick Draw, Quick Shape and the legends) writes the material on each hatch it makes with Remote>>Dyl:MaterialTagSet: its id ((car mat), the material joined to its hatch preset), the keys of mt:tag, a variable of the caller, and Role for a legend (Remote>>Dyl:MaterialTagsOf); the keys Tool, Preset, Assembly, Layer and Role of a former tool are dropped first. Remote>>Dyl:MaterialReplace (Replace hatches) writes it on the hatch it changes.
  • Without hatch – a material without pattern (Void) or a preset or layer with Has a hatch off makes no hatch: its closed outlines carry the material instead. Those made only to be hatched (No border: the outlines of a layer of an assembly, drawn apart by its Border lines and Dividing lines) were erased; they are now kept on the layer key *mt:regionkey* (MATREGION, layer A-Detl-Matl-Nplt, not plotted, in *lk:defaults* so a user copy of the layer keys gets it), so the region of an air space is still in the drawing. A legend box without hatch is still erased.
  • Quick Draw – Dyl:QuickDrawRun binds mt:tag to (("Tool" . "QuickDraw") ("Preset" . id)). Dyl:QuickDrawLayersGet gives each layer of an assembly its number (the 10th item of the layer), Dyl:QuickDrawLayerHatch passes it as the 8th item of each outline to hatch, and the Linear / Offset loop of Dyl:QuickDraw hatches each one with mt:tag bound to those keys and Assembly (column *mt:layerscol* of the material, unless it still holds the layers of an older file) and Layer.
  • Quick Shape – Dyl:QuickShapeRun binds mt:tag to (("Tool" . "QuickShape") ("Preset" . id)).
  • Pst-MaterialAssign – Dyl:MaterialSel takes the objects selected before the command (ssget "_I" with the types of *mt:tagtypes*) or asks for them, an open curve left out; Dyl:MaterialAssignDialog shows Res\Dyl-MaterialAssign.xaml: mat the list of Dyl:MaterialAssignList (None, then Group - Name by the order of (Remote>>Dyl:GroupsOf "Material"), then by name), on the material of the first object; cnt the number of objects; edm, the open button, closes with 2: the Materials window (Remote>>Dyl:MaterialDialog), then this one again, the list read again. Dyl:MaterialGive writes the id ("": None, the key removed) and drops the keys of the tool, in one undo mark.
  • Pst-MaterialMatch – picks an object with a material (asked again while the one picked has none), then gives it to the objects selected (Dyl:MaterialGive), the source left out.
  • Pst-MaterialShow – Dyl:MaterialShow: for one object, its material (Dyl:MaterialLabel: Name (Group), id (no longer exists)), its data in the units of the drawing (Dyl:MaterialDataText, the factors of *mt:data*, as the Materials window shows them) and its tool, preset and layer; for several, the count of each material.

Diagnostics

The Drawing section of Dyl-Diagnostics (dg:dwg-materials) counts the objects that carry a material, how many are closed outlines, the materials used and those of one's own, and reports a problem when a material used no longer exists. It gives counts only: the id of a material of one's own can name a client.

Limits

  • The outline kept for a region without hatch is not tied to the hatches around it: it is not stretched with an associative hatch, and stays when the wall is erased unless it is selected with it.
  • A material given to a block reference, a region or a solid is not read: explode it, or hatch it, first.
  • The data are not checked against the materials file when the drawing opens: a material deleted shows only in Pst-MaterialShow and Dyl-Diagnostics.
