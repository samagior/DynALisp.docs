Manager

The developer docs of the Manager: its files and how its code works. What it does and how to use it are in its User Guide page.

Source FilesModules\Dynalisp\Remote\Dyl-Manager.lsp (the tabs and the Manager, loaded at startup: the commands of every tool open it), Modules\Dynalisp\Apps\Draw\Dyl-Manager.lsp (the command Dyl-Manager), the Windows region of Resources\dynalisp.mnl (Dyl:WinShow, *dyl:wintabs*), Installer\Windows\Engine\Tabs.cs (the row of tabs and the picture left between two tabs, in DynALisp.Windows.dll)

The Tabs

A tab is a row of *dyl:mgrtabs*: (key title window app dialog run), its key as the commands name it ("QuickDraw"), its title, the window file of its tool (the window that gets the tabs), the Apps file of its tool (the Path of StartupSuite.csv), the function that shows the window of the tool and returns what to draw, and the function that draws it (nil for a tool that draws nothing).

A new tab is a row there: the window of a preset tool (Remote>>Dyl:PresetWin) needs nothing else, since the preset engine saves on the tab code. A window of another kind must treat *dyl:wintabcode* as its Save.

How It Works

  1. Remote>>Dyl:Manager (from c:Dyl-Manager with nil, from c:Dyl-QuickDraw, c:Dyl-QuickShape, c:Dyl-Materials and c:Dyl-HatchPresets with their key, from the Quick Draw Manager button of the Quick Draw Gallery) lists the tabs whose Apps file is turned on (Dyl:SuiteFileOn-p), with the tab asked for (Remote>>Dyl:ManagerTabs), and starts on that tab, else on *dyl:mgrlast*.
  2. For the tab shown it binds *dyl:wintabs*, (window titles index title place), and runs its dialog (Remote>>Dyl:ManagerShow, which loads its Apps file first when the function is not defined: an App turned on is only autoloaded).
  3. Dyl:WinShow gives the tabs to the window whose file is the window of that tab, and to no other (a window opened from the tab, Materials from Quick Draw, stays a sub-window): tab/list, tab, tab/title (*dyl:mgrtitle*, DynALisp - Manager) and tab/place (*dyl:mgrplace*).
  4. The plugin puts the row of tabs above the window (TabHost of Engine\Tabs.cs, left out of the ScrollViewer of Engine\Fit.cs, its height added to the window) and keeps the window at the place of tab/place whatever the tab. Another tab picked (a click, Ctrl+Tab, Ctrl+Shift+Tab, Ctrl+Page Down / Up) checks the values of the window as OK does, leaves a picture of it on the screen (Cover: a window without border, owned by AutoCAD, of the pixels of the window) and closes it with status 90 (TabHost.Status, *dyl:wintabcode*), the tab picked in tab. The picture is closed when the next window is drawn (ContentRendered), when AutoCAD is idle again (Application.Idle, in Bridge.cs: no other window was shown) or after 4 seconds.
  5. Dyl:WinShow sets *dyl:wintab* to the tab picked. Remote>>Dyl:PresetWin checks the presets got back as for Save (a value not valid shows the same tab again with its message, and *dyl:wintab* is cleared when it is shown again), then returns 2: the presets and the aliases are saved, and the dialog returns.
  6. Remote>>Dyl:Manager shows the tab of *dyl:wintab*, and stops once a window was closed otherwise (OK, Save, Cancel, Draw). It then runs the run function of the last tab on what its dialog returned: the preset Draw picked in the Quick Draw or the Quick Shape tab is drawn once the window is closed.

Each tab reads its files again when it is shown (the materials and hatch presets of the Quick Draw tab, the groups), so what another tab saved is there at once.
