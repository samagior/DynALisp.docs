Assistant

The developer docs of the Assistant: its files and how its code works. What it does and how to use it are in its User Guide page.

Source FilesModules\Dynalisp\Apps\Utilities\Dyl-Assistant.lsp, Installer\Assistant (DynALisp.Assistant.dll: Plugin.cs, Cli.cs, Chat.cs, Palette.cs, Json.cs, Server.cs, Tools.cs, Writes.cs, Host.cs)
DataModules\Dynalisp\Res\Assistant\Prompt.txt (its User copy when there is one), the working folder %LOCALAPPDATA%\DynALisp\Assistant
NeedsAutoCAD 2016 or later (the Net48 build references AutoCAD 2016, SeriesMin="R20.1"), Claude Code (claude.exe) installed and signed in by the user
SendsWhat the user types and what the tools read of the drawing, to Anthropic, through Claude Code; DynALisp itself sends nothing

How It Works

  1. c:Dyl-Assistant checks that the plugin is loaded (Dyl:AssistantShow), finds its docs page (Dyl:DocsPage, Dyl:DocsTarget) and its instructions (Dyl:UserFile of Res\Assistant\Prompt.txt), and calls (Dyl:AssistantShow docs prompt).
  2. The palette (Palette.cs, a PaletteSet holding a WPF view built in code, KeepFocus on) looks for Claude Code on a thread of its own (Cli.Find: the PATH, the PATH of the user, %USERPROFILE%\.local\bin, the Links folder of WinGet), its version (claude --version) and whether it is signed in (claude auth status --json, loggedIn). Until both are there it shows a banner: Install Claude Code opens a console running the installer of Anthropic (irm https://claude.ai/install.ps1 | iex), Sign in a console running claude auth login --claudeai.
  3. The first message starts one Claude Code for the conversation (Chat.cs): claude -p --input-format stream-json --output-format stream-json --verbose --include-partial-messages --model sonnet, the isolation options below and --append-system-prompt-file Prompt.txt. Each message is a line of JSON on its standard input; its events come back one JSON a line on a thread of their own, shown on the thread of the palette (Dispatcher): system/init (the session, kept; apiKeySource), stream_event (the text as it is written), assistant (a message whole, rendered: code blocks in Consolas, headings in bold), result (the end of the turn, its error).
  4. The first message also starts the server of the tools of the drawing (below) and gives it to Claude Code: --mcp-config with its URL and the header Authorization: Bearer ${DYL_ASSISTANT_TOKEN}, the token in that variable of the environment of Claude Code only (never on the disk nor its command line), --allowedTools with the tools that read, and --permission-prompt-tool mcp__dynalisp__approve for those that write. Each tool_use block of an assistant event adds a pale line to the conversation (Chat.ToolUse, Reading the layers...).
  5. Stop ends the process; the next message starts it again with --resume <session>, so the conversation goes on. A model picked ends an idle process the same way. New chat forgets the session. AutoCAD closing ends the process (Plugin.Terminate).

Claude Code

  • The account – the user signs in to the official Claude Code, unmodified, with their own Claude account; DynALisp runs that program and never reads, copies or sends its credentials, nor calls the API with them (the terms of Anthropic). Never --bare, which ignores the sign-in.
  • Isolation (Cli.Isolated) – --tools "" (no tool of Claude Code: no file, shell or web), --strict-mcp-config (no MCP server but that of DynALisp), --setting-sources project and --disable-slash-commands (no settings, hooks or plugins of the user), run in %LOCALAPPDATA%\DynALisp\Assistant. The CLAUDE_CODE_* variables of a Claude app that started AutoCAD are removed from its environment (Cli.StartInfo).
  • ANTHROPIC_API_KEY – kept: when it is set, Claude Code bills that key, not the subscription; the palette says so (and the apiKeySource of system/init when it is not none).
  • Windows – the arguments are quoted as CommandLineToArgvW reads them (Cli.Quote: .NET Framework has no ArgumentList), the standard input written as UTF-8 bytes without BOM on its stream (Cli.Write), the outputs read as UTF-8.

The Tools Of The Drawing

Server.cs is an MCP server in AutoCAD itself, over local HTTP (Streamable HTTP, JSON answers, no SSE stream), written by hand (the MCP SDK of C# needs ASP.NET Core, which .NET Framework does not have):

  • An HttpListener on http://127.0.0.1:<free port>/mcp/ (no administrator rights, no URL reservation), started by the first message of the palette and stopped when AutoCAD closes. A token of 32 random bytes is made at each start; a request without Authorization: Bearer <token> gets 401, one with an Origin header (a web page) 403, a GET 405.
  • JSON-RPC 2.0: initialize (the protocol version of the client echoed), ping, tools/list, tools/call; a notification gets 202, any other method -32601 (server/discover, asked before initialize). Each request is answered on a thread of its own, so a call waiting for the user never holds the others.
  • Host.cs runs every tool on the main thread of AutoCAD, through the Dispatcher kept when the plugin loads (Plugin.Initialize): a reading in a transaction that changes nothing (StartOpenCloseTransaction), at any time, even while a command waits for a point; a change in the command context (ExecuteInCommandContextAsync, the reason for AutoCAD 2016) between _.UNDO _Begin and _.UNDO _End, one U. A change is refused while CMDACTIVE is not 0 (a command, a Lisp command, a window of DynALisp open), and when the active drawing is not the one approved.

CMDNAMES after it tells Claude when the command still waits.

A tool answers JSON text, coordinates in drawing units and angles in degrees, rounded to 6 decimals; a list gives 200 items a page at most (Claude Code takes 25 000 tokens of a tool), a write 500 objects a call at most. An item that fails stops the whole change (its transaction is not committed), the error naming the item.

Approval

  1. Before a tool that writes, Claude Code calls approve (--permission-prompt-tool; Claude does not see it) with tool_name, input and tool_use_id. Tools.Approve refuses a tool that is not a write of DynALisp, checks the input and says in one sentence what it does (Tools.Summary: Create 3 polylines and 1 hatch on A-WALL), a bad input denied with its error so Claude fixes it.
  2. Palette.Ask shows the card (the sentence, the drawing, the command line of run_command; Allow, Allow for this chat, Deny) and highlights the objects it changes while it waits, 9 minutes at most (Claude Code waits 10: timeout of --mcp-config). Stop and New chat deny the cards still waiting.
  3. approve keeps the drawing approved for that tool_use_id and answers {"behavior":"allow","updatedInput":...} or {"behavior":"deny","message":...}. The tool then runs (its _meta gives the same claudecode/toolUseId) in that drawing only, and a call no approval matches is refused. Allow for this chat answers the next calls of the same tool without a card until New chat (Tools.ForgetApprovals), never for run_command.

Functions For Other Apps

  • (Dyl:ClaudeRun input system model schema timeout) – one request without the palette: claude -p --output-format json --model <model> (haiku when nil), the isolation options, --no-session-persistence, the instructions in a temporary file (--system-prompt-file, deleted after), --json-schema when a schema is given, the input on its standard input; timeout in seconds (120 when nil). Returns (T text), the text of the answer or the JSON of its structured_output, or (nil error). AutoCAD waits for it. Check (if Dyl:ClaudeRun ...) first. Text Fix uses it.
  • (Dyl:ClaudeInfo) – (("path" . p) ("version" . v) ("loggedIn" . "1") ("authMethod" . m) ("apiKey" . "1") ("server" . port)), for Dyl-Diagnostics, server empty until the palette starts the tools; only path (empty) and apiKey when Claude Code is not found.

Diagnostics And Uninstall

dg:dyl-assistant (section DynALisp of Dyl-Diagnostics), when Dyl-Assistant is turned on: the plugin loaded, the path and version of Claude Code, whether it is signed in and how, a note when ANTHROPIC_API_KEY is set, and the port of the server of the tools when it listens. The uninstall removes the working folder and the conversations Claude Code kept for it (%USERPROFILE%\.claude\projects\*-DynALisp-Assistant, CleanAssistant of DynALisp.iss); Claude Code and its sign-in stay.

Limits

  • Not yet: the presets, materials, assemblies and layer keys of DynALisp (they need the Lisp side, Dyl:AssistantCall), AutoLISP, a picture of the view, the Undo button of a card.
  • A command of run_command that does not get all its answers stays active for the user to finish; a command that opens a window waits for it.
  • The palette is built in code, so Installer\Windows\Shots cannot draw its picture.
  • Claude Code installed with npm (claude.cmd) is not found: the native installer or WinGet is needed.
