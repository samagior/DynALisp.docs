Command Optimizer

The developer docs of Command Optimizer: its files and how its code works. What it does and how to use it are in its User Guide page.

Source FilesModules\Dynalisp\Apps\Output\Dyl-CmdOptimizer.lsp (the commands redefined), the PrepBeforeOutput region of Resources\dynalisp.mnl (the steps, their file, UNDEFINE / REDEFINE, the output prep window), Prep Drawing (the steps run)
DataModules\Dynalisp\Res\PrepSuite.csv (the steps of each column, your copy under User); the user setting DynalispPrepRedefine

The Redefined Commands

Each command of MAJ:cmds is a Lisp command of the same name in Dyl-CmdOptimizer.lsp, turned on or off in Dyl-Suite as any other:

(defun c:QSAVE ()
  (if MAJ:PrepFor (MAJ:PrepFor "QSAVE"))   ; the steps of its column
  (vl-cmdf "_.QSAVE")                        ; the native command, even undefined
  (princ)
)

The dialog commands call (initdia) first, so their window opens. MAJ:groups puts them in four groups that share one column of steps, named by their first command (MAJ:PrepCol): SAVE (SAVE, QSAVE, SAVEAS, +SAVEAS), PLOT (PLOT, PUBLISH, EXPORTPDF, EXPORTDWF, EXPORTDWFX), PREVIEW and REGEN.

Redefining, Step By Step

  1. As DynALisp loads, when DynalispPrepRedefine is on (MAJ:Redefine-p), (MAJ:Redefine T) runs. MAJ:synced keeps the setting this drawing applied.
  2. MAJ:Redefine loads AcPublish.crx when it is not (AutoCAD loads PUBLISH on demand, which would bring the native command back), then, with CMDECHO 0 and NOMUTT 1, runs _.UNDEFINE on each command of MAJ:CmdsOn (the Lisp commands defined in this drawing, their autoload stubs included) and _.REDEFINE on the others: a native command is never undefined without its Lisp command.
  3. MAJ:RedefineSet (the Commands checkbox of Dyl-Settings, and c:Dyl-CmdOptimizer, which asks [On/Off]) writes the setting and redefines this drawing at once. The other open drawings follow when they become current: the settings reactor finds MAJ:synced different and Dyl:SetSync sends MAJ:RedefineSync (UNDEFINE cannot run from a reactor).
  4. c:Dyl-RestoreCommands runs (MAJ:Redefine nil) for the session only.
  5. MAJ:Status gives the line of the startup summary: the commands redefined, or why they are native.

The Steps Of A Command

  1. (MAJ:PrepFor cmd) does nothing while the setting is off. Otherwise MAJ:PrepLoad loads Dyl-PrepDrawing.lsp the first time (it is autoloaded with its own command only), and MAJ:PrepDrawing runs (MAJ:PrepSteps cmd).
  2. MAJ:PrepRead reads PrepSuite.csv again before every command, so a change applies to every open drawing at once: Step;Description;SAVE;PLOT;PREVIEW;REGEN, 1 runs the step. A file, step or column missing uses MAJ:PrepDefault (REGEN: the draw order only).
  3. The steps are the rows of MAJ:steps: LAYERS, UNHIDE, XREFS, DATALINKS, TABLES, DRAWORDER, DRAWORDERCLEAN, REGEN (see Prep Drawing).

The Output Prep Window

The window is Res\Dyl-Settings-OutputPrep.xaml (a Windows file): a checkbox per step and column, key t_<step>_<column> (MAJ:PrepDlgKey), given by MAJ:PrepWinVals and read back by MAJ:PrepWinGet, with All On / All Off (dyl:Win.SetAll). A step added to MAJ:steps gets its row in the file. MAJ:PrepDlg shows it. Opened by Dyl-PrepSuite, OK saves it at once (MAJ:PrepWrite, through Dyl:UserFileW); opened from Dyl-Settings, it is saved with the other settings (MAJ:PrepSave).

Known Limitations

  • UNDEFINE lasts for the session, the Lisp commands are defined per drawing: a drawing whose startup stopped before the modules loaded has neither (_.QSAVE still works).
  • -PLOT and -PUBLISH are left out of MAJ:groups: (command "-PLOT" ...) fails while a command is undefined.
  • +SAVEAS leaves its prompts to the user or to the menu macro that called it.
