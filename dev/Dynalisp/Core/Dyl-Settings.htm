Settings

The developer docs of Settings: its files and how its code works. What it does and how to use it are in its User Guide page.

Source FilesThe Settings region of Resources\dynalisp.mnl, Modules\Dynalisp\Res\Dyl-Settings.dcl; the readers and setters of each setting in the Remote file of its tool
FollowsThe Settings convention

Where The Settings Are

The settings are Windows user settings of AutoCAD (getenv / setenv): DynalispReactors, DynalispSettingsSync, DynalispSetupOn, DynalispSysVarOn, DynalispDisplayOn, DynalispAutoUpdate, DynalispCleanStartup, DynalispRevisionSync, DynalispLanguage, DynalispShrinkGapImperial / Metric... A setting is on only when it is "1", so a setting never saved is off; DynalispLanguage holds English or French. If the reactors keep AutoCAD from starting, turn them off from the command line: (setenv "DynalispReactors" "0"), then open the drawings again.

The Window, In The Code

  1. c:Dyl-Settings reads every setting into its locals (st:aph auto-phase, st:rea the reactors, st:lng the language...) and keeps them as they were in st:old.
  2. Dyl:SetDlgFill shows them, Dyl:SetDlgRea greys out the reactor toggles while the master switch is off, and Dyl:MoreTile draws each open button, greyed out while its toggle is off or its tool is not loaded.
  3. An open button closes the window, runs its window (Dyl:SetRun: Dyl:SetPhases, Dyl:SetObjectKeys, Dyl:SetDrawOrder, Dyl:SetSysVars, Dyl:SetRevBlocks), then opens it again; Dyl:SetDefsDlg, Dyl:SetPrefsDlg and Dyl:SetDisplayDlg are the sub-windows of the region itself.
  4. Save runs Dyl:SetApply with st:old: only what changed is written and applied to this drawing (Remote>>Dyl:PhaseAutoSet, MAJ:RedefineSet, Remote>>Dyl:PrefApply...). Cancel writes nothing.
  5. The other open drawings follow when they become current: the settings reactor (Reactor\Dyl-SettingsSync.lsp, while Settings sync is on) runs Dyl:SetSync, which applies only what changed since the drawing last synced (DS:synced, MAJ:synced, SV:synced).

Adding A Setting

A new setting is a Dynalisp* user setting, off on a new installation (read with (= "1" (getenv ...))), a toggle of the window with its short description, a slot of st:old, its line in Dyl:SetApply, its check in Diagnostics, and, when it means something on this computer only, a name of *dyl:setslocal*.
