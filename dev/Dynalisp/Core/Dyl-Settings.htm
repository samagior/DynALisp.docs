Settings

The developer docs of Settings: its files and how its code works. What it does and how to use it are in its User Guide page.

Source FilesThe Settings region of Resources\dynalisp.mnl, Modules\Dynalisp\Res\Dyl-Settings.xaml and its sub-windows (Dyl-Settings-DrawingSettings.xaml, -Display, -FilePreferences, -OutputPrep), shown by the Windows plugin; the readers and setters of each setting in the Remote file of its tool

Where The Settings Are

The settings are Windows user settings of AutoCAD (getenv / setenv): DynalispReactors, DynalispSettingsSync, DynalispSetupOn, DynalispSysVarOn, DynalispDisplayOn, DynalispAutoUpdate, DynalispAssistantLisp, DynalispCleanStartup, DynalispSheetSetReopen, DynalispStartPage, DynalispActivity, DynalispRevisionSync, DynalispLanguage, DynalispShrinkGapImperial / Metric... A setting is on only when it is "1", so a setting never saved is off; DynalispLanguage holds English or French. If the reactors keep AutoCAD from starting, turn them off from the command line: (setenv "DynalispReactors" "0"), then open the drawings again.

The Window, In The Code

  1. c:Dyl-Settings reads every setting into its locals (st:aph auto-phase, st:rea the reactors, st:lng the language...) and keeps them as they were in st:old.
  2. Dyl:SetWinVals turns them into the values of the window and of its sub-windows (Dyl:SetDefsVals, Dyl:SetDisplayVals, Dyl:SetPrefsVals, MAJ:PrepWinVals), a setting greyed out when its Remote file or its command is not loaded; Dyl:WinShow shows Dyl-Settings.xaml. The window greys out itself the reactor toggles while the master switch is off, and each open button while its toggle is off (dyl:Win.EnabledBy).
  3. The open buttons of Drawing Settings, Commands, File Preferences and Display open their sub-window over it, on the same values (dyl:Win.Open): its OK keeps them, its Cancel puts them back. The other open buttons close the window with their number (4 to 8), Dyl:SetWinGet keeps what was changed, the command runs (Dyl:SetRun: Dyl:SetPhases, Dyl:SetDrawOrder, Dyl:SetSysVars, Dyl:SetObjectKeys, Dyl:SetRevBlocks), then the window opens again.
  4. Save reads the values back (Dyl:SetWinGet) and runs Dyl:SetApply with st:old: only what changed is written and applied to this drawing (Remote>>Dyl:PhaseAutoSet, MAJ:RedefineSet, Remote>>Dyl:PrefApply...). Cancel writes nothing.
  5. The other open drawings follow when they become current: the settings reactor (Reactor\Dyl-SettingsSync.lsp, while Settings sync is on) runs Dyl:SetSync, which applies only what changed since the drawing last synced (DS:synced, MAJ:synced, SV:synced).

The Display Settings

The Display window (Res\Dyl-Settings-Display.xaml) sets the colors of AutoCAD, the same in every drawing, from Remote\Dyl-EnvColor.lsp: DynalispInterface (the whole interface, a name of *ec:looks*), DynalispBackground (model space) and DynalispLayoutBackground (the paper of the layouts), each a name of *ec:colors* that takes the place of the one of the Interface, and DynalispFileTabColors (the band of colour of the file tabs, Project or Sheet set, FileTabs.cs of the same plugin, greyed out when Dyl:RibbonFileTabs is not defined), empty when it is not set. *ec:prefs* lists them in order, and st:bkg holds their values in that order; *dyl:setdisplay* names the popup of each (ifc, bkg, lbk, ftb). The theme of AutoCAD (COLORTHEME) is never set: it is the one chosen in AutoCAD, and the Interface applies only to its dark theme. Remote>>Dyl:DisplayWant gives what a context is set to, its own choice or else the colors of the look; a background is set with its crosshair color (GraphicsWinModelBackgrndColor and ModelCrosshairColor, GraphicsWinLayoutBackgrndColor and LayoutCrosshairColor of the Display preferences); the background around the paper, the Paper background setting of the profile (setenv), which Options does not show and AutoCAD may read only when the layout is shown again, always comes from the look. DynALisp is the dark of the windows (Theme of Installer\Windows\Engine\Session.cs): model space and the background around the paper #181B20 (a little darker than their title bar, without being black), paper #252A32 (their background), crosshairs #E6EAF0 (their text); a colour changed there is changed in *ec:looks* too. DynALisp Neutral is its variant in a neutral grey, darker: model space and the background around the paper #121212, paper #1E1E1E, crosshairs #E6E6E6, and for the rest of the interface the Look.Neutral of the plugin. Remote>>Dyl:DisplayApply, a step of the startup and run again when Settings is saved, sets only what differs. The rest of the interface is colored by DynALisp.Ribbon.dll (see Ribbon), which reads DynalispDisplayOn and DynalispInterface itself and again when (Dyl:RibbonSkin) is called (Remote>>Dyl:DisplayOnSet, DisplayPrefSet, DisplayApply). The former settings DynalispRibbonColors and DynalispPaletteColors are read as the Interface while it is not set, and cleared with DynalispColorTheme when the display settings are saved.

Adding A Setting

A new setting is a Dynalisp* user setting, off on a new installation (read with (= "1" (getenv ...))), a checkbox of Dyl-Settings.xaml with its short description and its value in Dyl:SetWinVals / Dyl:SetWinGet (and in the sample values of its picture, Installer\Windows\Shots\Samples\Dyl-Settings.txt), a slot of st:old, its line in Dyl:SetApply, its check in Diagnostics, and, when it means something on this computer only, a name of *dyl:setslocal*.
