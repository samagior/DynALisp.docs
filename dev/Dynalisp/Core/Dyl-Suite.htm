Startup Suite

The developer docs of Startup Suite: its files and how its code works. What it does and how to use it are in its User Guide page.

Loading The Modules

  1. Dyl:load, as each drawing opens, loads the Remote folders of every module (alphabetical order) but those of the library modules (*dyl:libmods*: LeeMac, gileCAD), then the Reactor folders while the reactors are on, keeping the errors and times of each file for the diagnostics.
  2. Dyl:autoload reads StartupSuite.csv and, for each command turned on, defines an autoload stub (autoload): the Lisp file loads the first time one of its commands runs. A command of another module than Dynalisp gets a stub of its own (Dyl:LibAutoload, Dyl:LibRun), which first loads the Remote folders of the library modules, once in the drawing (Dyl:LibsLoad, their times kept in *dyl:libtimes*). A command turned off is not defined.
  3. Dyl:AliasApply defines each alias of Aliases.csv as a command that runs its command, unless the name is taken by AutoCAD, its Express Tools, acad.pgp or another program (Dyl:AliasTaken, Dyl:PgpAliases).
  4. Dyl:DynList asks each provider of *dyl:dynproviders* for its dynamic children (the custom presets of Quick Draw and Quick Shape) and defines them with their main command.

The Index

  • c:Dyl-SuiteUpdate scans the Apps files (Dyl:SuiteFiles) and builds the index again (Dyl:SuiteBuild), keeping the Load value of each command, and of a renamed one when its former name is one of its aliases.
  • Dyl:SuiteParse reads a Lisp file as tokens: after (defun, a name starting with C: is a command, named and described by the last two comment lines before it (Dyl:SuiteFlush). See Making A Module.
  • Dyl:SuiteStale-p tells an index older than its Apps files: Dyl:Suite then builds it again at startup, parsing only the files changed since it was written (after a git pull, an update), the commands of the others taken from the index (Dyl:SuiteRecsOf, the keep of Dyl:SuiteBuild); Dyl-SuiteUpdate parses them all. Dyl:SuiteRead and Dyl:SuiteWrite read and write it through Dyl:UserFile; the index and Aliases.csv are read with Dyl:SuiteCsv, which takes their rows from Core (Dyl:Data, divided once for the session) while it is loaded, and written with Dyl:SuiteCsvDone, which tells it.

The Window

The Startup Suite window is a WPF window (Windows): Res\Dyl-Suite.xaml, shown by c:Dyl-Suite with Dyl:WinShow. Its list runs in the window itself, with no call to the Lisp while it is open:

  1. c:Dyl-Suite reads the records (Dyl:SuiteRecs), adds the dynamic children (Dyl:SuiteDlgDyn, sets dyns) and puts each child right after the main command of its file (Dyl:SuiteDlgOrder, sets mains and nkids; Dyl:SuiteChild-p: a Pst-* command, or any other command of a file with a Dyl-* or LM-* main command).
  2. Dyl:SuiteWinRow makes a row of each record for the window (ste/rows): its columns of StartupSuite.csv, then its main command, its number of children, preset or dynamic child, main command of its file, what opens its docs page (Dyl:SuiteDocs, Dyl:DocsTarget), the page it would have and its Lisp file, found once per file. Dyl:SuiteWinTaken gives the names an alias cannot take (ste/taken): the Lisp commands of the other programs, the aliases of acad.pgp, and what has the name of an alias saved (Dyl:AliasTakenOther).
  3. The window (SuiteEditor of Suite.cs) lists them: the Module, Group and Show lists, the search (command, aliases, name, description, file), the sort (each child keeps the key of its main command), the folding of the children, On/Off (a main command gives its value to its dynamic children), the aliases (refused as Dyl:SuiteDlgAliasCheck did: never a long name with a command prefix, nor a name taken), and opens the docs and the Lisp files itself (10 at most).
  4. It closes with 1 (Save), 0 (Cancel) or 3 (Open in VS Code), and gives back ste/rows and ste/als as edited and the state of its list (Dyl:SuiteWinState: the sort, Show, the search, the two checkboxes, ste.mod, ste.grp, ste.opens, ste.sel). On 3, Dyl:VSCode runs and the window opens again on them, as it was. On 1, Dyl:SuiteWinBad refuses an alias added with the name of an AutoCAD command (getcname, which the window cannot ask): the window opens again with its message (error).
  5. The sort is kept in DynalispSuiteSort and the files unfolded in *dyl:suiteopen* (Save or Cancel). On Save, Dyl:SuiteSave writes Aliases.csv and StartupSuite.csv (asked again while a file is open in another program), then asks whether to apply them now (Dyl:autoload, Dyl:AliasApply).

The questions of the Startup Suite and of the other tools (Dyl:SuiteAsk, Dyl:Ask, Dyl:AskIn) are the small window Res\Dyl-Ask.xaml: its title (win/title), its lines (msg) and the labels of its two buttons (yes, no: the label of a button named by the Lisp). Without the plugin, the question is asked on the command line.

Another App checks that a file is on with Dyl:SuiteFileOn-p, turns it on with Dyl:SuiteFileOn after asking, and loads it with Dyl:SuiteFileLoad.

Visual Studio Code

c:Dyl-VSCode and Open in VS Code call Dyl:VSCode: Dyl:VSCodeExe finds Code.exe (the install folders of the user and of the computer, then the folders of the PATH holding code.cmd), and Dyl:VSCodeOpen opens *dyl:repo in it with the Windows shell (Dyl:VSCodeShell). When it is not found, Dyl:VSCodeGuide shows Res\Dyl-VSCode.xaml: Install (winget) closes it with 2 and Download page with 3, the Lisp starts them and shows it again with what to do next (msg); Open DynALisp (1) returns Code.exe once it is found, else shows it again. Without the plugin, the steps are written on the command line.
