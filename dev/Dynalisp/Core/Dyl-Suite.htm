Startup Suite

The developer docs of Startup Suite: its files and how its code works. What it does and how to use it are in its User Guide page.

Loading The Modules

  1. Dyl:load, as each drawing opens, loads the Remote folders of every module (alphabetical order), then the Reactor folders while the reactors are on, keeping the errors and times of each file for the diagnostics.
  2. Dyl:autoload reads StartupSuite.csv and, for each command turned on, defines an autoload stub (autoload): the Lisp file loads the first time one of its commands runs. A command turned off is not defined.
  3. Dyl:AliasApply defines each alias of Aliases.csv as a command that runs its command, unless the name is taken by AutoCAD, its Express Tools, acad.pgp or another program (Dyl:AliasTaken, Dyl:PgpAliases).
  4. Dyl:DynList asks each provider of *dyl:dynproviders* for its dynamic children (the custom presets of Quick Draw and Quick Shape) and defines them with their main command.

The Index

  • c:Dyl-SuiteUpdate scans the Apps files (Dyl:SuiteFiles) and builds the index again (Dyl:SuiteBuild), keeping the Load value of each command, and of a renamed one when its former name is one of its aliases.
  • Dyl:SuiteParse reads a Lisp file as tokens: after (defun, a name starting with C: is a command, named and described by the last two comment lines before it (Dyl:SuiteFlush). See Making A Module.
  • Dyl:SuiteStale-p tells an index older than its Apps files; Dyl:SuiteRead and Dyl:SuiteWrite read and write it through Dyl:UserFile.

The Window

Dyl:Suite works on the locals recs (every record), vis (the records listed), sel (the selected), als (the aliases being edited). The list folds the children under their main command (Dyl:SuiteDlgFold), sorts and filters (Dyl:SuiteDlgSort, Dyl:SuiteDlgModules, Dyl:SuiteDlgGroups), and keeps its scroll when a few lines change. The aliases are checked as they are typed (Dyl:SuiteDlgAliasCheck: never a long name with a command prefix, nor a name taken). Docs opens Dyl:SuiteDocs, the page named after the Lisp file, on the website or on this computer. Dyl:SuiteSave writes both files and loads the changes.

Another App checks that a file is on with Dyl:SuiteFileOn-p, turns it on with Dyl:SuiteFileOn after asking, and loads it with Dyl:SuiteFileLoad.

Visual Studio Code

DYL-VSCODE (or Open in VS Code) opens the DynALisp folder in Visual Studio Code, to read or edit the programs. When Visual Studio Code is not found, a window guides the install: Install (winget) installs it with the Windows package manager, Download page opens its download page, Open DynALisp checks again and opens the folder once it is installed.
