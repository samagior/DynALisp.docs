Info And User Files

The developer docs of Info And User Files: its files and how its code works. What it does and how to use it are in its User Guide page.

Source FilesThe Info and UserFiles regions of Resources\dynalisp.mnl, the windows Res\Dyl-Info.xaml, Res\Dyl-WhatsNew.xaml and Res\Dyl-UserFiles.xaml (of the Dynalisp module)
DataThe AppVersion of PackageContents.xml, What's New (CHANGELOG.md and CHANGELOG.fr.md), the latest release of *dyl:relrepo*; the User folder
FollowsThe Versions And Updates and User Files conventions

Versions And Updates

  • Dyl:InfoVersion reads AppVersion, the one place the version is kept; Dyl:InfoNewer-p compares two versions.
  • Dyl:InfoCheck reads the latest release of the public releases repository (Dyl:InfoLatest through Dyl:InfoHttp, short timeouts), and keeps *dyl:latest*: (VERSION PAGE-URL SETUP-URL NOTES-URL), or NONE when it could not be read. Once per drawing, when the window opens.
  • What's new (Dyl:InfoWhatsNew, Dyl:InfoNotes) shows the sections of What's New, CHANGELOG.md, written for the users only (what they can do now and where to find it, never how the code changed: that is the history of git), its format at its top: a ## <version> - <date> section per version, a ### <title> per change, then its text (a line starting with - a line of its own), a picture ![](path) and a link [Open the docs](path), the paths from the root of the repository (Contents/Modules/Dynalisp/Docs/Core/Dyl-Settings.htm#display). Dyl:InfoParse reads it (Dyl:InfoLines in UTF-8, Dyl:InfoMd drops the marks of Markdown), Dyl:InfoPick keeps the versions asked (## Next, merged and not released yet, for a git clone only), Dyl:InfoLocal puts in their place those of the copy in the language of DynALisp (CHANGELOG.fr.md, Dyl:InfoFiles; a version it lacks stays in English), and Dyl:InfoRows makes the rows of the window: the picture a file of this computer (its -dark copy in the dark theme) or its address on the docs website (Dyl:InfoPic: the setup does not install the docs), the link what opens the page in the language of DynALisp (Dyl:InfoLink, through Dyl:DocsTarget, its #anchor kept on the website), dropped when the page is nowhere. After an update, Dyl:UpdWhatsNew shows the new versions once. Before one, Dyl:InfoUpdate downloads the CHANGELOG.md of the release and its copy in the language of DynALisp (Dyl:InfoLatest, Dyl:InfoFetch, to %TEMP%\DynALisp). The release workflow attaches both files to the release, and Installer\Build.ps1 makes its notes of the section of the version, its paths pointed to the docs website.
  • Update to... (Dyl:InfoUpdate) downloads the setup (Dyl:InfoDownload) and starts it (Dyl:InfoRun); the setup waits for AutoCAD to close. Dyl:InfoGit-p tells a git clone, which is never updated this way.
  • Dyl:UpdAuto, a startup step, does it by itself while DynalispAutoUpdate is on, at most once a day (DynalispUpdateChecked).

User Files

  • (Dyl:UserFile path) returns the user copy of a data file when there is one (Dyl:UserPath: the same path under DynALisp.bundle\User), else the default; (Dyl:UserFileW path) the copy to write, made from the default the first time. Dyl:UserDir and Dyl:UserDirW do it for a folder whose files are added and deleted, copied whole and marked by _UserFolder.txt.
  • c:Dyl-UserFiles lists the copies (Dyl:UserItems), resets one (deletes the copy) or makes it the default (copies it under Contents: how an edit is published).
  • Export settings and Import settings (Dyl:SetsExport, Dyl:SetsImport) write and read a DynALisp Settings <date> folder: DynALisp-Settings.txt (every Dynalisp* setting as Name=Value, the local ones of *dyl:setslocal* left out), User\ and Modules\MyTools\; the setup and the uninstall use the same format (Installer\DynALisp.iss).

The Windows

The three are WPF windows (see Windows), shown with Dyl:WinShow. Nothing calls the Lisp back while one is open, so each button that runs Lisp closes it with its number (the comment at the top of each window file lists them), and the Lisp does the work and shows it again on the values it got.

  • Info (Res\Dyl-Info.xaml) – c:Dyl-Info gives the version, the update status and the label of the update button (Dyl:InfoWinUpd, greyed out when there is nothing to update), the modules with a docs index, on the website or on this computer (Dyl:DocsFind), and the core commands defined (*dyl:core*, command TAB what it does, shown in two columns by dyl:Cell). The update button (3) runs Dyl:InfoUpdate, whose message replaces the status when the install failed; What's new (4), Check again (5), GitHub repository (6) and Open docs index (7) do their work, then the window opens again on the command and the module picked. Run, or a command double-clicked (dyl:Win.Close on the list), closes it with 2: the command runs once the window is closed.
  • What's New (Res\Dyl-WhatsNew.xaml) – Dyl:InfoNotesDlg gives the line above the changes (hed), the changes (lst/list, one item each, its columns divided by tabs: the heading of its version on the first change of each one, its title, its text, its picture, what opens its link and the label of the link, each shown by dyl:Cell as its target needs it and hidden when empty; the list is read, not picked: Dyl.Note), the line under them (msg) and the label of Install (ins, greyed out when nil). All releases (3) opens the releases page and shows it again; Install (2) returns T.
  • User Files (Res\Dyl-UserFiles.xaml) – c:Dyl-UserFiles reads the copies again (Dyl:UserWinFill) each time it shows it, with the line of what was done (msg). Open (2, or an item double-clicked), Open User folder (3), Reset to default (4) and Make it the default (5) work on the item selected; Reset and Make it the default do it on the second click of the same button on the same item (uf:arm, taken back by any other button; Dyl:UserWinDo). Export settings (6, Dyl:UserWinExport) and Import settings (7, Dyl:UserWinImport) ask for their folder or file once the window is closed. When a file changed (uf:done), the cached presets are read again and the aliases defined again.
